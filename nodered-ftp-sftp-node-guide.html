🖥️🍓 ローカル/ラズパイ 環境とは？

このガイドで扱うノードについて

FTP と SFTP のノードは Node-RED の標準ノードに含まれていない追加パッケージである。使うのは次の2つ。

パッケージ 版（執筆時点） 提供するノード ライセンス
node-red-contrib-ftp v0.0.8（2022-06-20 公開） ftp in（FTP クライアント）
sftp in（SFTP クライアント）		 Apache
node-red-contrib-ftp-server v1.0.4（2022-03-19 公開） ftp server（FTP サーバー） MIT
  • GitHub: joeartsea/node-red-contrib-ftp（作者 Atsushi Kojo）
  • GitHub: biddster/node-red-contrib-ftp-server（作者 @biddster）

node-red-contrib-ftp は日本語の表示ファイルを同梱している。そのため設定項目は原則として日本語表示をそのまま示し、訳語が用意されていない項目だけ「English Label（日本語訳）」の形式で書く。node-red-contrib-ftp-server は日本語表示を持たないため、すべて英語ラベルに訳を添える。

免責： 本ガイドは上記バージョンでの動作を前提に書いている。どちらも 2022 年以降の更新がなく、Node-RED 本体や Node.js の更新で挙動が変わる可能性がある。導入前に最新の状況を確認してほしい。

SFTP サーバーのノードは存在しない：

Node-RED を SFTP のサーバーにするノードは、2026-08-13 時点で npm 上に見つからない。かつて候補だったパッケージは公開が取り下げられている。SFTP は SSH の機能の一つなので、サーバー側は OS の SSH デーモンで用意する。手順はセクション 8 で扱う。

1. 概要：ファイルを受け渡す4つの立ち位置

現場でファイル転送が必要になる場面は、たいてい次のどちらかである。計測器が日次の CSV を吐くので回収したい。ネットワークカメラが動体検知の画像を送りつけてくるので受け止めたい。前者は Node-RED が取りに行く側、後者は Node-RED が受ける側になる。

取りに行く側をクライアント、受ける側をサーバーと呼ぶ。これに暗号化の有無を掛け合わせると、立ち位置は4つになる。

立ち位置 何をするか 使うもの
FTP クライアント 相手の FTP サーバーへ接続し、ファイルを取得したり送ったりする ftp in ノード
SFTP クライアント 同じことを SSH の上で行う sftp in ノード
FTP サーバー Node-RED 自身が待ち受け、機器から送られたファイルを受け取る ftp server ノード
SFTP サーバー 同じことを暗号化して行う OS の OpenSSH（Node-RED のノードは無い）

どの立ち位置になるかは、相手の機器が決めることが多い。カメラや計測器の設定画面に「FTP サーバーのアドレス」を入れる欄があれば、機器がクライアントで Node-RED がサーバーである。逆に相手が置き場所を用意しているだけなら、Node-RED が取りに行く。

ファイルの中身を扱う手前の話：

転送したファイルを Node-RED の中で読み書きするのは、標準の file ノードの役目である。フォルダにファイルが増えたことを検知するのは watch ノードが担う。このガイドは「マシンの間でファイルを動かす」部分だけを扱う。

2. FTP と SFTP と FTPS の違い

名前が似ている3つを並べて整理する。

FTP FTPS SFTP
通信の暗号化 なし TLS SSH
既定のポート 21（制御用）とデータ用の別ポート 21 または 990 22
認証 ID とパスワード（平文で流れる） ID とパスワード ID とパスワード、または公開鍵
土台になる仕組み FTP という独立したプロトコル FTP に TLS をかぶせたもの SSH の機能の一つ
このガイドで扱う手段 ftp in と ftp server 扱わない sftp in と OS の OpenSSH

誤解されやすいのは SFTP の位置づけである。名前は FTP に S が付いた形だが、FTP を暗号化したものではない。SSH という別の仕組みの中に用意されたファイル転送機能であり、プロトコルもポートも FTP とは無関係である。FTP を暗号化したものは FTPS のほうで、こちらは名前が紛らわしいわりに現場で見かける機会が少ない。

平文 FTP の危険：

FTP はユーザー名とパスワードを暗号化せずに送る。同じネットワークを流れるパケットを見られる立場の相手には、そのまま読み取られる。ファイルの中身も同様である。

使ってよいのは、外部から到達できない LAN の中と検証環境に限る。インターネットを越えてファイルを運ぶ用途では SFTP か FTPS を選ぶ。古い機器が FTP しか話せない場合は、機器と Node-RED を同じ閉じたネットワークに置き、そこから先を SFTP で中継する構成にする。

パッシブモードとアクティブモード

FTP には、他のプロトコルにあまり無い癖がある。命令のやり取りとファイルの中身を、別々の接続で運ぶ。この2本目をどちらから張るかで2つのモードに分かれる。

パッシブ（PASV）モード クライアント ──接続──> サーバー （制御用、ポート 21） クライアント ──接続──> サーバー （データ用、サーバーが指定したポート） アクティブモード クライアント ──接続──> サーバー （制御用、ポート 21） クライアント <──接続── サーバー （データ用、クライアントが指定したポート）

アクティブモードはサーバーからクライアントへ接続を張るため、クライアント側にファイアウォールがあると弾かれる。そのため現在はパッシブモードが既定になっている。

サーバーを立てる側から見ると、パッシブモードでは制御用のポートに加えてデータ用のポートも開けておく必要がある。どのポートを使うかはサーバーが接続のたびに選ぶため、既定のままだと範囲が定まらずファイアウォールの設定を書けない。ftp server ノードの「Passive Mode Port Range」は、この範囲を固定するための欄である。

3. インストール方法

Node-RED エディターの「パレットの管理」から導入する。2つのパッケージを別々に入れる。

  1. エディター右上のメニュー（三本線）から「パレットの管理」を開く
  2. 「ノードを追加」タブを選ぶ
  3. 検索欄に node-red-contrib-ftp と入力し、「ノードを追加」ボタンを押す
  4. 続けて node-red-contrib-ftp-server を検索し、同じように追加する
  5. インストール後、パレットの「ストレージ」に ftp と sftp、「入力」に ftp server が現れる

コマンドラインから入れる場合は、Node-RED のユーザーディレクトリ（多くは ~/.node-red、Windows では %userprofile%\.node-red）で次を実行する。

npm install node-red-contrib-ftp node-red-contrib-ftp-server
SFTP も同じパッケージに入っている：

node-red-contrib-ftp というパッケージ名からは FTP だけに見えるが、中には sftp ノードも同梱されている。SFTP を使うために別のパッケージを探す必要はない。

メンテナンスの状況：

どちらのパッケージも 2022 年以降の更新がない。node-red-contrib-ftp が内部で使う ftp パッケージはさらに古い。動いているうちは問題ないが、Node.js や Node-RED を新しくしたときに壊れる可能性はある。

SFTP クライアントだけが必要で、更新の新しさを重視するなら node-red-contrib-sftp-ssh2（v0.1.4、2024-07-20）という別の選択肢もある。ただし設定項目の作りが異なるため、本ガイドの説明はそのまま当てはまらない。

4. ノード構成

5種類のノードが登場する。うち2つは接続先を保持するコンフィグノードで、フロー上には現れない。

ftp（コンフィグ）

接続先の FTP サーバーの住所と認証情報を持つ。複数の ftp in ノードから共有できる。

ftp in

FTP クライアント

メッセージを受けて一度だけ接続し、指定した操作を行って結果を出す。

sftp（コンフィグ）

接続先の SFTP サーバーの情報を持つ。パスワードのほか秘密鍵も指定できる。

sftp in

SFTP クライアント

ftp in と同じ操作を SSH の上で行う。一覧の絞り込みができる点が異なる。

ftp server

FTP サーバー

入力を持たず、指定ポートで待ち受ける。ファイルが届くと出力へ流す。

inject → ftp in（取りに行く） → debug
ftp server（待ち受ける） → file → debug

ftp in と sftp in は入力を持つ。inject や他のノードからメッセージが届いたときに、はじめて接続して転送を行う。常時つながっているわけではない。

5. 設定項目一覧

node-red-contrib-ftp は日本語の表示ファイルを持つため、エディターの多くの欄は日本語で表示される。訳語が用意されていない欄だけ英語のまま表示されるので、その場合は英語ラベルに訳を添えて示す。

ポート 制御用の接続に使うポート番号。 21
ユーザ名 認証に使うユーザー名。 anonymous

接続タイムアウト 制御用の接続が確立するまで待つ時間（ミリ秒）。相手が応答しない場合にここで打ち切る。 10000
PASVタイムアウト パッシブモードのデータ接続が確立するまで待つ時間（ミリ秒）。ファイアウォールでデータ用ポートが塞がれていると、ここで時間切れになる。 10000

FTPS は当てにしないほうがよい：

「Data connection encryption」のチェックボックスは、ソースを読むと入力欄の id がコンフィグノードの命名規則（node-config-input- で始まる形）から外れている。他の欄と揃っていないため、チェックした値が保存されない可能性がある。

暗号化した転送が必要なら、このチェックボックスに頼らず SFTP を使う。相手が FTPS しか話せないなら、Node-RED のノードではなく exec ノードから curl や lftp を呼ぶ構成のほうが確実である。

「ファイル名」と「ローカルファイル名」は、msg.filename と msg.localFilename でも渡せる。ただし優先されるのはノードの設定であり、欄に何か書いてあると、そちらが常に勝つ。メッセージごとにファイル名を変えたい場合は、ノードの欄を空にしておく。

ローカルとはどのマシンか：

「ローカルファイル名」が指すのは、Node-RED が動いているマシンのファイルシステムである。ブラウザを開いているマシンではない。Raspberry Pi の Node-RED を手元の PC から操作している場合、ここに書くのは Pi 側のパスになる。

鍵認証を勧める理由：

パスワードをコンフィグノードへ書くと、Node-RED の資格情報ファイルに保存される。鍵認証にすれば、Node-RED 側に持つのは秘密鍵ファイルのパスだけになり、鍵そのものは OS のファイルパーミッションで守れる。鍵は接続元のマシンで ssh-keygen -t ed25519 で作り、公開鍵だけを接続先の ~/.ssh/authorized_keys へ登録する。

6. 操作ごとの挙動

6つの操作それぞれについて、することと出力される msg.payload を整理する。

Operation すること 出力される payload
list ディレクトリの中身を一覧する ファイル情報の配列。名前、種別、サイズ、更新日時などを含む
get サーバーのファイルをローカルへ保存する Get operation successful. に続けてローカルのパスを並べた文字列
put ローカルのファイルをサーバーへ送る FTP は Put operation successful. という文字列。SFTP は転送結果の文字列
append サーバー側の既存ファイルの末尾へ書き足す Append operation successful. という文字列
delete サーバー側のファイルを削除する 実質的に空
mkdir サーバー側にディレクトリを作る。途中の階層も作られる FTP は mkdir operation successful. という文字列
get はファイルの中身を返さない：

最も間違えやすい点である。get は取得したファイルをローカルへ書き出すだけで、msg.payload に入るのは成功を伝える文字列にすぎない。中身を Node-RED の中で使いたいなら、get の後ろに file in ノードを繋いで、保存されたファイルを読み直す。

sftp in（get） → file in（保存先を読む） → debug

操作のあと、メッセージには実際に使われたパスが書き戻される。msg.filename と msg.localFilename は常にセットされ、SFTP ではこれに加えて msg.path と msg.pattern も付く。後段でログを残すときに使える。

失敗したときの振る舞い

接続できない、ファイルが見つからない、権限がない、といった失敗が起きると、ノードは出力へ何も流さずエラーを発生させる。ノードのステータスは赤くなり、エラーメッセージが表示される。

このエラーは catch ノードで捕まえられる。転送は相手のマシンやネットワークの状態に左右されるため、失敗したことに気づける経路を用意しておく。

ftp in ✗ catch → debug（通知）

7. FTP サーバーとして受け取る

ftp server ノードは入力を持たず、デプロイした時点でポートを開いて待ち受ける。出力は2つある。

出力 ラベル いつ流れるか メッセージの中身
1 upload file ファイルが送られてきたとき msg.topic にファイル名、msg.payload にファイルの中身（Buffer）
2 authenticate Username 欄が空のとき、接続のたび msg.payload に {username, password}、msg.authenticate に判定を返す関数
受け取ったファイルはディスクに残らない：

このノードはメモリ上の仮想ファイルシステムにファイルを書き、5秒後に消す。Raspberry Pi のような機器でメモリを使い切らないための作りである。

そのため、出力1をどこにも繋がなければファイルは失われる。保存したいなら file ノードへ繋いで自分で書き出す。「FTP サーバーを立てたのにファイルがどこにも見当たらない」という詰まり方は、ほぼこれが原因である。

動的認証モード

Username 欄を空にすると、ユーザー名とパスワードの判定をフロー側で行う。接続のたびに出力2へメッセージが流れるので、function ノードで msg.authenticate(true) または msg.authenticate(false) を呼んで返事をする。

// 出力2 に繋いだ function ノード // パッケージの公式ヘルプに載っている書き方に沿っている msg.authenticate( msg.payload.username === 'camera' && msg.payload.password === 'change-me' ); msg.payload = undefined; return msg;

この仕組みが役に立つのは、機器ごとに違うユーザー名を使い分けたいときや、認証情報を環境変数から読みたいときである。判定を返さないと接続は成立しないため、出力2を使う設定にした場合は必ず繋いでおく。

TLS には対応していない：

このノードのヘルプには、TLS 対応が今後の課題として挙がったまま残っている。つまり通信は平文である。カメラなどの機器から画像を受ける用途では、機器と Node-RED を同じ閉じたネットワークに置く。

8. SFTP サーバーは OS 側で立てる

Node-RED を SFTP サーバーにするノードは、2026-08-13 時点で npm 上に存在しない。もっとも、SFTP は SSH の機能の一つなので、SSH サーバーが動いていれば、それがそのまま SFTP サーバーになる。Raspberry Pi OS や Ubuntu なら OpenSSH がその役目を担う。追加のパッケージは要らない。

手順

Raspberry Pi OS を例に、受け取り専用のユーザーを作るところまでを示す。

# 1. SSH を有効にする（無効な場合） sudo systemctl enable --now ssh # 2. 受け取り専用のユーザーを作る（ログインシェルは与えない） sudo useradd -m -s /usr/sbin/nologin sensor-upload sudo passwd sensor-upload # 3. 受信フォルダを用意する sudo mkdir -p /var/spool/sensor-upload sudo chown sensor-upload:sensor-upload /var/spool/sensor-upload # 4. 別のマシンから接続を確認する sftp sensor-upload@192.168.1.20

ここまでで、機器や別のマシンから SFTP でファイルを置けるようになる。Node-RED 側は転送そのものに関わらず、置かれたファイルを見つけて処理する役に回る。

watch（フォルダを監視） → file in（読む） → function（処理）

watch ノードに /var/spool/sensor-upload を指定すると、ファイルが増えたときにメッセージが流れる。

役割を分けておく利点：

転送を OS が担うため、Node-RED を再起動してもファイルの受け取りは止まらない。フローの編集中に届いたファイルも、あとから watch ノードや file in ノードで拾える。Node-RED 内で待ち受ける構成に比べて、止められる範囲が狭い。

書き込み途中のファイルを読まないようにする：

watch ノードはファイルが作られた時点でも反応するため、転送の途中で読みに行くと中身が欠けたファイルを掴むことがある。送信側で「一時的な名前で送り、完了後に本来の名前へ変える」運用にするか、受信側で delay ノードを挟んで少し待つ。

受け取り専用ユーザーを自分のフォルダの外へ出したくない場合は、OpenSSH の設定ファイル /etc/ssh/sshd_config で ChrootDirectory を使って閉じ込められる。ただし閉じ込め先のフォルダは所有者が root で、かつ他者に書き込み権限がないことが求められるなど条件が細かい。SSH と Linux の権限まわりは Linux ディレクトリガイドと本番運用ガイドも参照してほしい。

9. セキュリティと運用の注意

認証情報の置き場所

コンフィグノードのパスワード欄に入れた値は、フローをエクスポートしても書き出されない。Node-RED はこれを flows_cred.json という別のファイルへ暗号化して保存する。

ただし暗号化の鍵は、設定していなければ Node-RED が自動生成したものになる。フローファイルと資格情報ファイルを一緒にバックアップして別のマシンへ置くと、鍵が違うため復号できない。settings.js の credentialSecret を自分で決めておくと、移行のときに困らない。詳しくは settings ガイドを参照してほしい。

ポートを開ける範囲

FTP サーバーを立てる場合、開けるポートは制御用とデータ用の両方になる。「Passive Mode Port Range」を 7022-7032 のように決めておくと、ファイアウォールの設定を書ける。

# ufw を使っている場合の例（LAN からのみ許可する） sudo ufw allow from 192.168.1.0/24 to any port 7021 proto tcp sudo ufw allow from 192.168.1.0/24 to any port 7022:7032 proto tcp

ここで from を付けずに開けると、ルーターの設定によっては外部から届くようになる。平文の FTP を外部へ晒すことになるため、範囲は絞っておく。

手段の選び方

状況 選ぶもの
同じ LAN 内の古い機器からファイルを受ける ftp server ノード。ポート範囲を絞り、LAN からのみ許可する
別拠点やクラウドとファイルをやり取りする SFTP。鍵認証にする
相手から Node-RED へ送りつけてもらう（暗号化あり） OS の OpenSSH と watch ノード
相手が FTPS しか話せない exec ノードから curl や lftp を呼ぶ

12. まとめ

要点：
  • 立ち位置は4つある。取りに行くなら ftp in か sftp in、受けるなら ftp server か OS の OpenSSH
  • SFTP は FTP の暗号化版ではなく、SSH の機能の一つである。ポートも 22 で別物
  • get はファイルの中身を payload に返さない。ローカルへ保存するだけなので、中身を使うなら file in で読み直す
  • ftp server が受け取ったファイルはディスクに残らない。file ノードへ繋いで自分で保存する
  • SFTP のサーバー側は OS の OpenSSH が担う。Node-RED は watch ノードで置かれたファイルを拾う
  • 平文 FTP は LAN の中と検証用に限る。外へ出すなら SFTP を選ぶ

次に読むとよいガイド

  • file ノードガイド：転送したファイルを読み書きする
  • watch ノードガイド：フォルダに置かれたファイルを見つける
  • exec ノードガイド：FTPS や rsync など、ノードで足りない転送を外部コマンドで行う
  • 本番運用ガイド：受信フォルダの肥大化と保持期間の管理
  • Linux ディレクトリガイド：パスと権限の読み方

13. トラブルシューティング

症状 原因 対処
読み込んだフローが「不明なノード」になる パッケージが入っていない パレットの管理から node-red-contrib-ftp と node-red-contrib-ftp-server を入れる
get は成功したのに payload が文字列で、ファイルの中身が無い get はローカルへ保存するだけで、中身を payload に入れない 後段に file in ノードを繋ぎ、保存先のパスを読ませる
FTP サーバーで受けたファイルがどこにも見当たらない ノードはメモリ上に書いて5秒後に消す 出力1を file ノードへ繋いで保存する
msg.filename を渡しているのに無視される ノードの設定欄に値が入っており、そちらが優先されている ノードの「ファイル名」欄を空にする
接続はできるが list で何も返らない SFTP で対象を「ファイル名」欄に書いている SFTP の list は「ディレクトリパス」欄を使う
ログインは通るのに転送で止まる パッシブモードのデータ用ポートがファイアウォールで塞がれている サーバー側でポート範囲を固定し、その範囲を開ける
FTP サーバーに接続できない ポート 21 で接続しようとしている ノードの既定ポートは 7021。接続側の設定を合わせる
Username を空にしたら誰も接続できない 動的認証モードになり、出力2の判定待ちで止まっている 出力2に function ノードを繋ぎ、msg.authenticate(true) を呼ぶ
秘密鍵を貼り付けたが認証に失敗する 「秘密鍵」欄は鍵の中身ではなくファイルのパスを書く欄である /home/pi/.ssh/id_ed25519 のようにパスを書く
データ接続の暗号化にチェックしても平文のまま この欄は入力欄の id が他と揃っておらず、値が保存されない可能性がある SFTP を使うか、exec ノードから curl や lftp を呼ぶ
