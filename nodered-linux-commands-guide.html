1. ターミナルを開く・プロンプトを読む

開き方は3通り

方法 手順
デスクトップから 画面上部のターミナルのアイコンをクリック（Ctrl+Alt+T でも開く）
SSH で遠隔から PC 側のターミナル（Windows ならコマンドプロンプトや PowerShell）で ssh ユーザー名@ラズパイのIPアドレス
Node-RED から Exec ノードでコマンドを実行する（画面はないが、実行される場所は同じ）

プロンプトの読み方

ターミナルを開くと、次のような文字列が表示されます。これをプロンプトと呼び、入力待ちであることを示します。

taro@raspberrypi:~ $
taro：ログイン中のユーザー名 ／ raspberrypi：機器の名前（ホスト名） ／ ~：今いる場所（この場合はホーム）
$：一般ユーザーの印。root で作業していると # になる

記事に出てくる $ や # は入力しません

ネット上の解説で $ sudo apt update と書かれていたら、打つのは sudo apt update の部分だけです。先頭の $ は「ここからがコマンド」という目印にすぎません。本ガイドのコード欄には目印を付けていないので、そのままコピーできます。

2. コマンドの書式と調べ方

Linux のコマンドは、ほぼ例外なく次の3要素でできています。

ls -l /home/taro
コマンド：何をするか（一覧する）
オプション：どうやるか（詳しく表示する）。- か -- で始まる
引数：何に対してやるか（このフォルダに対して）

オプションは組み合わせられます。ls -l -a は ls -la とまとめて書けます。

使い方が分からなくなったら

調べ方 内容
コマンド名 --help オプションの一覧を短く表示する。まずはこれ
man コマンド名 詳しい説明書を開く。q で閉じる、↑↓ で移動
which コマンド名 そのコマンドの実体がどこにあるかを表示する

man から抜けられなくなったら q

man や less で開いた画面は、q（quit の q）で閉じます。プロンプトが戻ってこないときは、まず q、それでも駄目なら Ctrl+C を試してください。

3. 移動と確認（pwd / ls / cd）

ファイル操作は「今どこにいるか」を把握することから始まります。

コマンド 意味
pwd 今いる場所を絶対パスで表示する（print working directory）
ls 今いる場所のファイル一覧（list）
ls -l 権限・所有者・サイズ・日付付きで一覧する
ls -a 隠しファイル（. で始まる名前）も表示する
ls -lh サイズを KB/MB 単位の読みやすい形で表示する
cd フォルダ名 そのフォルダへ移動する（change directory）
cd .. 1つ上のフォルダへ戻る
cd（引数なし） ホームへ戻る。迷子になったときの帰還コマンド
cd - 直前にいたフォルダへ戻る
pwd /home/taro cd ~/.node-red ls -lh total 44K -rw-r--r-- 1 taro taro 4.5K Aug 5 09:12 flows.json -rw-r--r-- 1 taro taro 20K Jul 30 14:02 settings.js drwxr-xr-x 8 taro taro 4.0K Jul 30 14:05 node_modules cd pwd /home/taro

4. ファイル操作（mkdir / cp / mv / rm）

コマンド 意味
mkdir data data フォルダを作る
mkdir -p a/b/c 途中のフォルダもまとめて作る。既にあってもエラーにしない
touch memo.txt 空のファイルを作る（既存なら更新日時だけ変える）
cp 元 先 コピーする
cp -r 元 先 フォルダごとコピーする（recursive）
mv 元 先 移動する。名前の変更も同じコマンド
rm ファイル 削除する
rm -i ファイル 確認してから削除する。慣れるまではこちらが安全
rm -r フォルダ フォルダごと削除する

Linux の rm にゴミ箱はありません

削除したファイルは戻せません。特に rm -rf は確認なしで消し切るため、パスの打ち間違いが致命傷になります。慣れるまでは、消す前に ls で対象を確認する習慣をつけてください。

ls ~/data/old/ # 消す前に中身を確認 rm -r ~/data/old/ # 確認してから削除

設定ファイルを編集する前には、控えを取っておきます。この一手間が復旧を可能にします。

cp ~/.node-red/settings.js ~/.node-red/settings.js.bak

5. 中身を見る（cat / less / tail / grep）

コマンド 意味と使い分け
cat ファイル 全部を一度に表示する。短いファイル向け
less ファイル スクロールしながら読む。長いファイル向け。q で終了
head -n 20 ファイル 先頭20行だけ表示する
tail -n 50 ファイル 末尾50行だけ表示する。ログを見るときの基本
tail -f ファイル 追記されるのを待ち受けて表示し続ける。Ctrl+C で終了
grep 文字列 ファイル その文字列を含む行だけ抜き出す
grep -i 文字列 ファイル 大文字小文字を区別せずに探す
grep -rn 文字列 フォルダ フォルダ以下を再帰的に探し、行番号も表示する
wc -l ファイル 行数を数える
# CSV の先頭3行だけ確認する head -n 3 ~/data/sensor.csv time,temp,humid 2026-08-07T09:00:00,24.5,52 2026-08-07T10:00:00,25.1,51 # 設定ファイルからポート番号の行を探す grep -n "uiPort" ~/.node-red/settings.js 125: uiPort: process.env.PORT || 1880,

パイプとリダイレクト

コマンドは組み合わせられます。この2つを覚えると、できることが一気に広がります。

記号 意味 例
| 前のコマンドの出力を、次のコマンドの入力に渡す（パイプ） ls -l | grep json（一覧から json を含む行だけ表示）
> 出力をファイルに保存する（上書き） ls -l > list.txt
>> 出力をファイルの末尾に追記する date >> log.txt

> は既存の内容を消します

> は「ファイルを空にしてから書き込む」動作です。大事なファイルに対して打つと、中身が一瞬で消えます。追記したいときは必ず >> を使ってください。

6. ファイルを編集する（nano）

Linux には複数のテキストエディタがありますが、初心者が最初に使うべきなのは nano です。画面下部に操作方法が常に表示されるため、迷いません。

nano ~/.node-red/settings.js

システムの設定ファイル（/etc 以下）を編集するときは sudo が必要です。付け忘れると、編集はできても保存時に権限エラーになります。

sudo nano /etc/hostname

nano のキー操作

キー 動作
Ctrl+O → Enter 保存する（Write Out）。ファイル名の確認が出るので Enter
Ctrl+X 終了する。未保存なら保存するか聞かれる（Y → Enter）
Ctrl+W 文字列を検索する（Where is）
Ctrl+K カーソル行を切り取る
Ctrl+U 切り取った行を貼り付ける

画面下部の ^ は Ctrl キーのことです

nano の画面下に ^O Write Out と表示されているのは、「Ctrl+O で保存」という意味です。^ を Shift と勘違いしやすいので注意してください。

vi が開いてしまったときの脱出方法

コマンドによっては vi（または vim）という別のエディタが開くことがあります。これは操作方法が大きく異なり、そのままでは終了すらできません。Esc を押してから :q! と打って Enter で、変更を破棄して抜けられます。

7. 権限を扱う（chmod / chown / sudo）

①仕組み入門で説明した権限を、実際に操作するコマンドです。

権限を変える：chmod

指定方法は2通りありますが、初心者は記号の方式で十分です。

コマンド 意味
chmod +x script.sh 実行できるようにする。自作スクリプトを動かす前に必要
chmod -x script.sh 実行権限を外す
chmod 644 data.csv 所有者は読み書き、他は読むだけ（一般的なデータファイル）
chmod 755 script.sh 所有者は全部、他は読みと実行（一般的なスクリプト）

数字の意味は、読み＝4、書き＝2、実行＝1 の合計です。644 なら「所有者 6（4+2 で読み書き）、グループ 4（読み）、その他 4（読み）」となります。

chmod 777 を安易に使わないでください

誰でも読み書き実行できる状態になり、権限の意味が消えます。ネットの記事には「権限エラーは 777 にすれば直る」という記述が散見されますが、これは問題を隠しているだけで、セキュリティ上も危険です。正しい対処は、所有者を適切に設定する（chown）ことです。

所有者を変える：chown

# 誤って root の持ち物になったファイルを、自分の持ち物に戻す sudo chown taro:taro ~/data/sensor.csv # フォルダ以下すべてに適用する sudo chown -R taro:taro ~/.node-red

書式は ユーザー名:グループ名 です。ラズパイでは通常、ユーザー名とグループ名が同じになります。

自分が誰で、どのグループに属しているか

whoami でユーザー名、groups で所属グループを確認できます。GPIO やシリアルポートを扱うには gpio、dialout といったグループへの所属が必要で、権限エラーの原因がここにあることもあります。

8. プロセスと負荷（ps / top / kill / free）

コマンド 用途
ps aux 実行中のプロセスを全部表示する
ps aux | grep node-red Node-RED のプロセスだけを絞り込む
pgrep -a node node を含むプロセスの PID とコマンドを表示する
top CPU・メモリの使用状況を実時間で表示する。q で終了
free -h メモリの空き状況を表示する
uptime 連続稼働時間と負荷の平均値を表示する
kill PID番号 そのプロセスに終了を要求する
kill -9 PID番号 強制終了する。最後の手段。データが保存されないことがある
ps aux | grep node-red taro 842 2.1 8.4 1024364 82344 ? Ssl 09:00 0:31 node-red taro 1503 0.0 0.1 7360 644 pts/0 S+ 10:22 0:00 grep node-red

2行目は「今実行した grep 自身」が引っかかったものなので、無視して構いません。1行目の 842 が Node-RED の PID です。

Node-RED を止めるときに kill は使わないでください

サービスとして動いている Node-RED を kill で止めても、systemd が自動的に再起動させるため止まりません。正しくは sudo systemctl stop nodered です。kill が必要になるのは、手動で node-red と打って起動したプロセスが残ってしまった場合などです。

ラズパイでは、本体の温度と電源状態の確認も重要です。

vcgencmd measure_temp temp=48.3'C vcgencmd get_throttled throttled=0x0

throttled=0x0 なら正常です。0 以外の値は、電源の電圧不足や高温による性能制限が起きた記録を示します。原因不明の不安定動作は、電源アダプタの容量不足であることが少なくありません。

9. サービスとログ（systemctl / journalctl）

サービスの操作

systemctl status nodered # 状態を確認（sudo 不要） sudo systemctl start nodered # 起動 sudo systemctl stop nodered # 停止 sudo systemctl restart nodered # 再起動 sudo systemctl enable nodered # 自動起動を有効化 systemctl is-enabled nodered # 自動起動の設定を確認

status の出力で見るべきは次の2行です。

Loaded: loaded (/lib/systemd/system/nodered.service; enabled; ...) Active: active (running) since Fri 2026-08-07 09:00:11 JST; 1h 22min ago
表示 意味
Active: active (running) 正常に動いている
Active: inactive (dead) 止まっている
Active: failed 起動に失敗した。原因はログで確認する
enabled / disabled 自動起動が有効か無効か

ログを読む

コマンド 用途
node-red-log Node-RED のログを流し見る（公式スクリプト導入時）
journalctl -u nodered -f Node-RED のログを追い続ける。Ctrl+C で終了
journalctl -u nodered -n 100 直近100行だけ表示する
journalctl -u nodered --since "1 hour ago" 1時間前以降のログを表示する
journalctl -b 今回の起動以降のシステム全体のログ
journalctl -p err -b エラー以上のログだけに絞る

トラブル時の定番の流れ

「Node-RED が動かない」ときは、次の順で切り分けます。
① systemctl status nodered で動いているか確認 → ② 止まっていれば journalctl -u nodered -n 50 で直前のエラーを読む → ③ df -h でディスクの空きを確認 → ④ free -h でメモリを確認。
大半の原因はこの4つのどれかで見つかります。

10. ソフトの導入と更新（apt）

コマンド 意味
sudo apt update ソフト置き場の一覧（カタログ）を取り直す
sudo apt upgrade 導入済みのソフトを最新版に更新する
sudo apt install パッケージ名 新しく導入する
sudo apt remove パッケージ名 削除する（設定ファイルは残る）
sudo apt autoremove 不要になった依存パッケージを掃除する
apt search キーワード パッケージを検索する
apt list --installed 導入済みの一覧を表示する
# 定期メンテナンスの定番。update と upgrade は続けて実行する sudo apt update && sudo apt upgrade -y

&& は「前のコマンドが成功したら次を実行する」という意味です。-y は確認の質問にすべて「はい」と答えるオプションです。

Node-RED 本体の更新は apt ではありません

ラズパイの Node-RED は公式スクリプトで導入されるため、更新も専用のスクリプトで行います。apt upgrade では新しくなりません。更新手順はRaspberry Pi インストールガイドを参照してください。

Python で pip install が拒否されたら

bookworm 以降では、システムの Python を守るため pip install が externally-managed-environment というエラーで拒否されます。対処は、sudo apt install python3-〇〇 で apt から入れるか、python3 -m venv ~/myenv で専用の環境（仮想環境）を作ってその中で入れるかのどちらかです。

11. ネットワーク（ip / ping / ss / ssh）

コマンド 用途
hostname -I 自分の IP アドレスを表示する。最も手軽
ip a 全ネットワーク機器の詳細な状態
ping -c 4 8.8.8.8 相手に届くか4回試す。インターネット接続の確認
ping -c 4 google.com 名前解決（DNS）が効いているかの確認
sudo ss -tulpn 待ち受け中のポート一覧。1880 が出れば Node-RED が待機中
curl http://localhost:1880/ 自分自身の Node-RED に HTTP でアクセスしてみる
nmcli device wifi list 周囲の Wi-Fi 一覧（bookworm 以降）
ssh taro@192.168.1.50 他の機器へ遠隔ログインする
scp ファイル taro@192.168.1.50:~/ ファイルを別の機器へ転送する
hostname -I 192.168.1.50 # このアドレスを使い、PC のブラウザから http://192.168.1.50:1880/ で接続できる sudo ss -tulpn | grep 1880 tcp LISTEN 0 511 *:1880 *:* users:(("node-red",pid=842,fd=19))

切り分けの順番

「ブラウザから Node-RED に繋がらない」ときは、下の層から順に確認します。
① hostname -I で IP が取れているか（取れなければネットワーク未接続）→ ② PC からラズパイへ ping が届くか → ③ sudo ss -tulpn | grep 1880 で Node-RED が待機しているか → ④ curl http://localhost:1880/ でラズパイ自身からは繋がるか。
④ が成功して PC から繋がらない場合は、ネットワークやファイアウォールの問題に絞り込めます。

12. ストレージと時刻・終了

ストレージ

コマンド 用途
df -h 各領域の空き容量を表示する
du -sh ~/* ホーム直下の各フォルダの容量を表示する
lsblk 接続されているストレージと領域の一覧
sudo mount /dev/sda1 /mnt/usb USB メモリを手動で接続する（Lite 版など）
sudo umount /mnt/usb 取り外す。抜く前に必ず実行する

時刻

ラズパイには時計用の電池がなく、電源を切ると時刻を忘れます。通常はネットワーク経由で自動的に合わせるため、ネットワークに繋がらない環境では時刻がずれます。ログのタイムスタンプが妙なときは、ここを疑ってください。

date 2026年 8月 7日 金曜日 10:35:02 JST timedatectl Local time: Fri 2026-08-07 10:35:02 JST Time zone: Asia/Tokyo (JST, +0900) System clock synchronized: yes

終了と再起動

sudo reboot # 再起動 sudo shutdown -h now # 電源を切る準備をする

電源プラグを抜く前に必ずシャットダウンを

sudo shutdown -h now を実行し、緑色の LED が点滅しなくなってから電源を抜きます。この手順を省くと SD カードのファイルが壊れ、最悪の場合は OS が起動しなくなります。

13. 入力を速くする小技

コマンドを覚えるより、これらを先に体に入れたほうが作業は速くなります。

操作 効果
Tab 入力の補完。途中まで打って Tab を押すと続きが補われる。打ち間違いも防げる
Tab 2回 候補が複数あるとき、その一覧を表示する
↑ ↓ 過去に打ったコマンドを呼び出す
Ctrl+R 履歴を文字列で検索する。もう一度押すとさらに過去へ
Ctrl+C 実行中のコマンドを中断する
Ctrl+L 画面を消して見やすくする（clear と同じ）
Ctrl+D ターミナルを終了する（exit と同じ）
Ctrl+A / Ctrl+E 行頭 / 行末へカーソルを移動する
history 過去のコマンドを一覧表示する
* 任意の文字列を表す。ls *.csv で CSV だけ一覧

Tab 補完は最強の防御策です

cd ~/.no まで打って Tab を押せば cd ~/.node-red/ まで補われます。補完されないときは、そのパスが存在しないということです。打ち間違いをその場で検知できるので、長いパスほど Tab を使う価値があります。

ターミナルでの貼り付けは Ctrl+Shift+V

ターミナルでは Ctrl+V ではなく Ctrl+Shift+V で貼り付けます（Ctrl+C が中断の意味を持つため、コピーも Ctrl+Shift+C）。右クリックで貼り付けられる場合もあります。

14. Node-RED 運用の頻出コマンド15選

実際の運用で打つ機会が多いものをまとめました。この表だけ手元に置いても機能します。

# コマンド 場面
1 hostname -I ブラウザで接続するための IP を調べる
2 systemctl status nodered 動いているかを確認する
3 sudo systemctl restart nodered settings.js を変更したあとに反映する
4 journalctl -u nodered -f エラーの原因をログで追う
5 sudo systemctl enable nodered 電源投入時に自動起動させる
6 nano ~/.node-red/settings.js 設定を編集する
7 cd ~/.node-red && ls -lh フローや設定のファイルを確認する
8 df -h SD カードの空き容量を確認する
9 free -h メモリ不足を確認する
10 sudo apt update && sudo apt upgrade -y OS を最新に保つ
11 ls /dev/tty* シリアル機器が認識されたか確認する
12 sudo ss -tulpn | grep 1880 ポートの使用状況を確認する
13 cp ~/.node-red/flows.json ~/backup/ フローをバックアップする
14 vcgencmd measure_temp 本体の温度を確認する
15 sudo shutdown -h now 安全に電源を切る

15. Exec ノードから実行するときの注意

Node-RED の Exec ノードを使えば、フローの中からこれらのコマンドを実行できます。ただし、ターミナルで打つ場合とは条件が異なるため、次の3点に注意が必要です。

注意点 内容と対策
実行するユーザーが違う Node-RED をサービスとして動かしている場合、コマンドはそのサービスのユーザー権限で実行される。ターミナルで動いたのに Exec ノードでは権限エラーになるのはこのため
パスが通っていないことがある ターミナルとは環境変数が異なるため、コマンド名だけでは見つからない場合がある。which コマンド名 で調べた絶対パス（例：/usr/bin/vcgencmd）で書くと確実
sudo は使えないと考える パスワードを入力できないため、sudo が必要なコマンドは基本的に失敗する。どうしても必要なら sudoers の設定が要るが、セキュリティ上の判断が伴うため安易に行わない

まずターミナルで動かしてから Exec ノードに載せる

フローに書く前に、必ずターミナルで同じコマンドを実行して結果を確認してください。ターミナルで動かないものは Exec ノードでも動きません。逆に、ターミナルで動いて Exec ノードで動かない場合は、上の3点のどれかが原因です。

16. 打ってはいけないコマンド

ネット上のコピー＆ペーストで事故が起きやすいものを挙げます。意味が分からないコマンドは実行しないのが原則です。

コマンド 何が起きるか
sudo rm -rf / システム全体を削除する。復旧不可能
rm -rf ~ ホームディレクトリを丸ごと削除する。フローも設定も消える
sudo chmod -R 777 / 全ファイルの権限を壊す。セキュリティが崩壊し、起動しなくなることもある
sudo dd if=... of=/dev/mmcblk0 SD カードを直接上書きする。指定を誤ると OS ごと消える
sudo mkfs.ext4 /dev/sda1 指定した領域を初期化する。中のデータは全部消える
> 大事なファイル ファイルの中身が空になる

「とりあえず sudo を付ける」をやめる

上記のコマンドが致命傷になるのは、ほぼすべて sudo が付いているときです。sudo なしなら権限エラーで止まり、被害は出ません。sudo を打つときは一呼吸置いて、コマンドの意味を確認する。これだけで大半の事故は防げます。

17. 演習

演習1（初級）：バックアップを取る

ホームに backup というフォルダを作り、~/.node-red/flows.json をその中にコピーしてください。最後に、コピーされたことを一覧で確認します。

解答を見る
mkdir -p ~/backup cp ~/.node-red/flows.json ~/backup/ ls -lh ~/backup/

mkdir -p を使うと、フォルダが既にある場合でもエラーになりません。繰り返し実行する手順の中では、この形が扱いやすくなります。

演習2（初級）：ログからエラーを探す

Node-RED のログの直近100行から、Error という文字を含む行だけを表示してください。

解答を見る
journalctl -u nodered -n 100 | grep -i error

パイプ（|）で journalctl の出力を grep に渡しています。-i を付けているので error、Error、ERROR のいずれも拾えます。

演習3（中級）：容量を食っている犯人を探す

SD カードの空き容量が少なくなっています。① 全体の使用状況を確認し、② ホーム直下でどのフォルダが大きいかを調べ、③ /var/log の中で大きいものを特定してください。

解答を見る
df -h du -sh ~/* sudo du -sh /var/log/* | sort -h | tail -n 5

3行目の sort -h は容量の単位を理解して並べ替えるオプションで、tail -n 5 と組み合わせることで「大きいほうから5件」が得られます。Node-RED 環境では ~/.node-red/node_modules が数百 MB になっていることが多く、これは正常です。

演習4（中級）：ポートの使用状況を調べる

Node-RED を起動しようとしたら「ポート 1880 は使用中」というエラーが出ました。何が 1880 番を使っているかを特定してください。

解答を見る
sudo ss -tulpn | grep 1880

出力の末尾に users:(("node-red",pid=842,...)) のようにプロセス名と PID が表示されます。多くの場合、サービスとして動いている Node-RED がすでに 1880 番を使っているところに、手動で node-red を起動したことが原因です。手動起動をやめるか、sudo systemctl stop nodered でサービスを止めてから起動してください。

演習5（中級）：CPU 温度を記録する

CPU 温度の値を、時刻付きで ~/data/temp.log に1行追記するコマンドを書いてください（~/data は作成済みとします）。

解答を見る
echo "$(date '+%Y-%m-%d %H:%M:%S') $(vcgencmd measure_temp)" >> ~/data/temp.log

$( ) は「中のコマンドを実行し、その結果に置き換える」書き方です。>> で追記しているため、実行するたびに行が増えていきます（> にすると毎回上書きされ、1行しか残りません）。

Node-RED でやるなら、Inject ノード（繰り返し1分）→ Exec ノード（このコマンド）という2ノードで同じことが実現できます。定期実行を Linux の cron でやるか Node-RED でやるかは、フローと一緒に管理したいかどうかで選んでください。

18. まとめ

このガイドの要点

  • コマンドは「コマンド＋オプション＋引数」の3要素。困ったら --help
  • 移動と確認は pwd / ls -la / cd。迷子になったら cd だけ打てばホームへ戻る
  • ログは tail -f と journalctl -u nodered -f。トラブル対応の主戦場
  • 編集は nano。保存は Ctrl+O、終了は Ctrl+X
  • 権限エラーの正解は chmod 777 ではなく chown で所有者を直すこと
  • Tab 補完と ↑ 履歴を使うと、速さと正確さが同時に手に入る
  • sudo を打つ前に一呼吸。事故のほぼすべてはここで防げる
