A. 用語辞典（カテゴリ別）

1. OS の基礎

用語 意味
カーネル OS の中核。CPU・メモリ・機器を直接管理する。厳密にはこれ自体が「Linux」
ディストリビューション カーネルにコマンド群や設定を加えて配布物にまとめたもの。Debian、Ubuntu など
Debian Raspberry Pi OS のベースになっているディストリビューション
コードネーム Debian の版につく愛称。trixie（13）、bookworm（12）、bullseye（11）
シェル 打ち込んだコマンドを解釈して実行するプログラム。標準は bash
ターミナル 文字を表示し入力を受け取る「窓」。その中でシェルが動く
CLI / GUI 文字で操作する方式 / 画面をマウスで操作する方式
プロンプト 入力待ちを示す表示。taro@raspberrypi:~ $ の部分
ヘッドレス モニタ・キーボードを繋がず、ネットワーク越しに操作する運用形態
環境変数 シェルやプログラムが参照する設定値。echo $PATH で確認できる
PATH コマンドを探しに行くフォルダの一覧。ここにないコマンドは名前だけでは実行できない
シェルスクリプト コマンドを並べて書いたファイル。.sh が慣習。実行には実行権限が必要
標準出力 / 標準エラー出力 コマンドの通常の出力 / エラー用の出力。別々に扱える
リダイレクト 出力先をファイルに変えること。>（上書き）、>>（追記）
パイプ コマンドの出力を次のコマンドの入力に渡すこと（|）
cron 指定した時刻にコマンドを自動実行する仕組み。crontab -e で設定
ロケール / タイムゾーン 言語と文字の設定 / 時刻の地域設定。raspi-config で変更できる

2. ファイルとパス

用語 意味
ディレクトリ Windows でいうフォルダ
ルート（/） ツリーの最上位。管理者ユーザーの root とは別物
絶対パス / 相対パス / から始まる完全な住所 / 今いる場所を起点にした住所
ホームディレクトリ 利用者ごとの作業場所。/home/ユーザー名、略記は ~
隠しファイル 名前が . で始まるファイル。ls -a で表示される
シンボリックリンク 他のファイルを指す目印。Windows のショートカットに近い。ls -l で l と表示される
マウント ストレージをツリーの一部として繋ぐこと。USB メモリは /media/... に繋がれる
アンマウント 接続を解除すること。取り外す前に必要（umount）
パーティション ストレージを区切った領域。SD カードは起動用と本体用の2つ
ファイルシステム データの記録形式。Linux 本体は ext4、起動領域は FAT32
inode ファイルの管理情報。数が尽きると、容量が空いていてもファイルを作れなくなる
スワップ メモリが足りないときに、ストレージを一時的なメモリとして使う領域

3. ユーザーと権限

用語 意味
root すべての操作が許された管理者ユーザー
sudo そのコマンド1回だけを管理者として実行する仕組み
グループ ユーザーのまとまり。dialout（シリアル）、gpio（GPIO）などの所属で権限が決まる
パーミッション 読み（r）・書き（w）・実行（x）の許可。rw-r--r-- のように表示される
所有者 そのファイルを持っているユーザー。chown で変更する
実行権限 スクリプトを動かすために必要な許可。chmod +x で付与する
sudoers 誰がどのコマンドを sudo できるかの設定。編集は visudo で行う

4. プロセスとサービス

用語 意味
プロセス 実行中のプログラム。メモリ上に存在する実体
PID プロセスに割り振られる番号。kill するときに指定する
デーモン 画面を持たず裏で常駐するプロセス。名前の末尾が d のものが多い
サービス systemd が管理する常駐プログラム。Node-RED もこの形で動く
systemd サービスの起動・停止・自動起動を統括する仕組み。最初に起動するプロセス（PID 1）
ユニット systemd が扱う設定の単位。nodered.service がその1つ
enable / start 次回以降の自動起動を設定する / 今すぐ起動する。別の操作
ジャーナル systemd が集めるログ。journalctl で読む
シグナル プロセスへの合図。Ctrl+C は中断、kill -9 は強制終了の合図
終了コード コマンドの結果を表す数値。0 が成功、それ以外は失敗。echo $? で確認できる

5. ソフトの管理

用語 意味
パッケージ インストール可能な形にまとめられたソフト
リポジトリ パッケージの公式な置き場所（配布元のサーバー）
apt パッケージを取り寄せて導入・更新・削除する道具
dpkg apt の下で実際にパッケージを展開する仕組み。.deb ファイルを直接扱う
依存関係 そのソフトが動くために必要な別のソフト。apt が自動で解決する
npm Node.js のライブラリを管理する道具。Node-RED の追加ノードはこちら
仮想環境（venv） Python で、システムと切り離した専用の環境を作る仕組み
armhf / arm64 32bit 版 / 64bit 版の CPU 種別。パッケージの対応可否に関わる

6. ネットワーク

用語 意味
IP アドレス ネットワーク上の住所。hostname -I で確認する
ホスト名 機器の名前。初期値は raspberrypi。raspberrypi.local で参照できることもある
ポート 1台の機器の中でサービスを区別する番号。Node-RED は 1880
localhost / 127.0.0.1 自分自身を指す名前とアドレス
DHCP IP アドレスを自動で配る仕組み。再起動でアドレスが変わることがある
DNS 名前を IP アドレスに変換する仕組み
SSH 暗号化された遠隔操作の仕組み。ラズパイ運用の主要な入り口
NetworkManager bookworm 以降のネットワーク管理の仕組み。nmcli / nmtui で操作する
ファイアウォール 通信を選別する仕組み。ラズパイの標準構成では通常無効

7. ラズパイ固有

用語 意味
Raspberry Pi Imager SD カードに OS を書き込む公式ツール。ユーザー名や SSH の初期設定もここで行う
raspi-config ラズパイ用の設定ツール。sudo raspi-config で起動する
Control Centre trixie でデスクトップの設定画面が統合されたアプリ
config.txt ハードウェア設定のファイル。/boot/firmware/ にある（bookworm 以降）
GPIO 基板上のピン。センサーや LED を接続する入出力端子
I2C / SPI / UART 機器と通信する方式。使う前に raspi-config で有効化が必要
スロットリング 高温や電圧不足のときに性能を落とす保護動作。vcgencmd get_throttled で確認
Lite 版 デスクトップ画面を含まない軽量版の Raspberry Pi OS
Wayland / labwc 現在のデスクトップ画面を描画している仕組み（bookworm 以降）

B. エラーメッセージ逆引き

実際に画面に出るメッセージから、原因と対処を引けるようにまとめました。

Permission denied

-bash: /etc/hostname: Permission denied

意味：そのファイルを操作する権限がない。

対処：システムの領域なら sudo を付ける（sudo nano /etc/hostname）。自分のホーム内でこれが出る場合は、過去に sudo で作ったせいで所有者が root になっている可能性が高い。ls -l で所有者を確認し、sudo chown ユーザー名:ユーザー名 ファイル名 で戻す。

command not found

-bash: nmcli: command not found

意味：そのコマンドが見つからない。

対処：① 綴りを確認する（Tab 補完を使えば防げる）。② そもそも入っていない場合は sudo apt install パッケージ名 で導入する。③ 入っているのに出る場合は PATH の問題なので、which や ls /usr/bin/ で実体を探し、絶対パスで実行する。

No such file or directory

cat: /home/taro/data/Sensor.csv: No such file or directory

意味：指定したパスにファイルがない。

対処：大文字と小文字の違いを最初に疑う（Sensor.csv と sensor.csv は別物）。次に ls で本当に存在するか確認する。相対パスで打っている場合は pwd で現在地を確認する。

Error: listen EADDRINUSE: address already in use :::1880

Error: listen EADDRINUSE: address already in use :::1880

意味：1880 番ポートを既に別のプロセスが使っている。

対処：サービスとして動いている Node-RED があるところに、手動で node-red を起動したケースがほとんど。sudo ss -tulpn | grep 1880 で使用者を特定し、手動起動をやめるか、sudo systemctl stop nodered でサービスを止めてから起動する。

externally-managed-environment

error: externally-managed-environment × This environment is externally managed

意味：システムの Python を守るため、pip install が拒否された（bookworm 以降の仕様）。

対処：① sudo apt install python3-パッケージ名 で apt から入れる。② python3 -m venv ~/myenv で仮想環境を作り、source ~/myenv/bin/activate してから pip install する。--break-system-packages での強行は避ける（システムの Python を壊す恐れがある）。

Unable to locate package

E: Unable to locate package nodejs

意味：そのパッケージがカタログに見当たらない。

対処：まず sudo apt update でカタログを取り直す。それでも出る場合は、パッケージ名の綴り違いか、そのリポジトリに存在しないパッケージ。apt search キーワード で正しい名前を探す。

No space left on device

Error: ENOSPC: no space left on device, write

意味：ストレージが満杯。フローの保存もログの記録もできない状態。

対処：df -h で確認し、sudo du -sh /var/log/* | sort -h | tail で犯人を特定する。ログが原因なら sudo journalctl --vacuum-size=100M で古いジャーナルを削減できる。sudo apt autoremove と sudo apt clean も効果がある。

Read-only file system

touch: cannot touch 'test.txt': Read-only file system

意味：書き込み禁止の状態になっている。SD カードの異常を検知して、保護のため読み取り専用に切り替わった可能性が高い。

対処：SD カードの寿命または破損を疑う。まず flows.json などの重要ファイルを別の場所へ退避し、journalctl -p err -b でストレージ関連のエラーを確認する。再起動で一時的に戻ることもあるが、根本的にはカードの交換が必要。

Connection refused

curl: (7) Failed to connect to 192.168.1.50 port 1880: Connection refused

意味：そのアドレスには届いたが、指定のポートで待ち受けているものがない。

対処：アドレスまでは到達しているので、原因はサービス側。systemctl status nodered で Node-RED が動いているかを確認する。動いていない場合は journalctl -u nodered -n 50 で起動失敗の原因を読む。

ssh: connect to host ... Connection timed out

ssh: connect to host 192.168.1.50 port 22: Connection timed out

意味：相手まで届いていない。

対処：① IP アドレスが変わっていないか確認する（DHCP では変わることがある）。② ラズパイの電源とネットワークの接続を確認する。③ SSH が有効になっているか確認する（sudo raspi-config の Interface Options）。

WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@ @ WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED! @ @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

意味：以前に接続した相手と鍵が違う。OS を再インストールしたときや、同じ IP を別の機器が使い始めたときに出る。

対処：心当たり（再インストール等）があるなら、PC 側で古い記録を消す：ssh-keygen -R 192.168.1.50。心当たりがない場合は、接続先が本当に目的の機器かを確認してから対処する。

sudo: a terminal is required to read the password

sudo: a terminal is required to read the password

意味：パスワードの入力が必要だが、入力できない状況にある。Exec ノードやスクリプトから sudo を実行したときに出る。

対処：フローから sudo を使わない設計に変える。どうしても必要なら sudoers の設定が要るが、セキュリティ上の判断が伴うため慎重に。2026年4月以降の新規インストールでは sudo にパスワードが必要になった点も併せて確認する。

C. 症状別トラブルシューティング

ブラウザから Node-RED に繋がらない
  1. hostname -I でラズパイの IP を確認する（表示されなければネットワーク未接続）
  2. アドレスが変わっていないか確認する。ブラウザには http://その IP:1880/ と入力する
  3. systemctl status nodered で active (running) かを確認する
  4. 動いていなければ journalctl -u nodered -n 50 でエラーを読む
  5. ラズパイ自身から curl http://localhost:1880/ を試す。ここで成功して PC から失敗するなら、ネットワーク側の問題
電源を入れ直したら Node-RED が起動しない

自動起動の設定が有効になっていない可能性が最も高いです。

systemctl is-enabled nodered disabled sudo systemctl enable nodered

enabled と表示されるのに起動しない場合は、起動時のエラーを journalctl -u nodered -b で確認してください。flows.json が壊れていると起動に失敗します。

フローを保存したのに、再起動すると消えている
  • ディスクが満杯で保存に失敗している：df -h を確認する
  • ファイルが読み取り専用になっている：ls -l ~/.node-red/flows.json で権限と所有者を確認する
  • 複数の Node-RED が別々のユーザーディレクトリで動いている：起動ログの User directory の表示を確認する
  • 電源を直接抜いた：書き込み途中のデータが失われる。sudo shutdown -h now で終了する習慣をつける
動作が急に遅くなった・不安定になった
  1. vcgencmd measure_temp で温度を確認する（80℃ を超えると性能が落ちる）
  2. vcgencmd get_throttled が 0x0 以外なら、電源の容量不足か高温が起きている
  3. free -h でメモリの空きを確認する
  4. top で CPU を占有しているプロセスを特定する
  5. df -h でディスクの空きを確認する

ラズパイの不安定動作は、電源アダプタの容量不足が原因であることが少なくありません。公式または相応の出力を持つアダプタを使ってください。

USB シリアル機器（MODBUS など）が認識されない
  1. 挿す前後で ls /dev/tty* を実行し、増えたものを特定する
  2. 何も増えなければ、ケーブルやドライバの問題。dmesg | tail -n 20 で接続時のログを確認する
  3. デバイスは見えるのに権限エラーが出る場合は、dialout グループへの所属を確認する：groups
  4. 所属していなければ sudo usermod -aG dialout ユーザー名 を実行し、再ログインする（反映には再ログインが必要）
SSH で入れなくなった
  1. IP アドレスが変わっていないか確認する。ルーターの管理画面や、ping raspberrypi.local を試す
  2. それでも不明なら、モニタとキーボードを繋いで直接 hostname -I を実行する
  3. 鍵の警告が出る場合は、上の「REMOTE HOST IDENTIFICATION HAS CHANGED」を参照する
  4. 固定 IP にしておくと、この問題の大半は起きなくなる

D. 困ったときの初動チェックリスト

原因が分からないときは、この5つを順に実行してください。ほとんどの問題は、この段階で当たりがつきます。

systemctl status nodered # ① 動いているか journalctl -u nodered -n 50 # ② 直前に何が起きたか df -h # ③ ディスクは空いているか free -h # ④ メモリは足りているか hostname -I # ⑤ ネットワークに繋がっているか

エラーメッセージは省略せずに読む

Linux のエラーは、多くの場合「何が」「どこで」「なぜ」失敗したかを含んでいます。cat: /home/taro/data/Sensor.csv: No such file or directory なら、cat が、そのパスで、ファイルがないために失敗した、と読めます。検索するときも、この3要素を含めたほうが的確な情報にたどり着けます。
