1. 概要

Complete ノードとStatus ノードは、他のノードの動作状況を監視するためのノードです。Catch ノード（エラー監視）と合わせて、フローの監視に使用します。

✅ Complete ノード

Complete

役割: 指定ノードの処理完了を検知

用途:

  • 非同期処理の完了検知
  • 処理時間の計測
  • 後続処理のトリガー

📊 Status ノード

Status

役割: 指定ノードのステータス変化を検知

用途:

  • 接続状態の監視（MQTT等）
  • 処理状況の表示
  • エラー状態の早期検知

工場のラインに例えると：Complete ノードは「作業完了」のランプ、Status ノードは機械の「状態表示パネル」のようなものです。作業が終わったか、今どんな状態かをリアルタイムで把握できます。

動作を図で見る

2 つのノードは、どちらも入力の端子を持たず、別のノードを見張っていて、何かが起きたときに msg を送り出します。

2. Complete ノード詳細

プロパティ

設定項目説明
対象ノード（「ノードを選択...」）完了を監視するノードを選ぶ。「ノードを選択...」ボタンを押し、フロー上のノードを複数選択する。Complete ノードには固定ラベルの入力欄はなく、この選択リストが本体となる
名前エディター上のノード表示名

出力メッセージ

{ "payload": /* 完了したノードが最後に出力した payload */, "_msgid": "元のメッセージID", /* 元のメッセージの全プロパティを継承 */ }

Complete が発火するタイミング

  • ノードが node.done() を呼び出したとき
  • ノードがメッセージ処理を完了したとき
  • 非同期処理（HTTP Request など）が完了したとき

ポイント:

Complete に対応するのは一部のノードです。主に非同期処理を行うノード（HTTP Request、Exec、File など）で有効です。

3. Status ノード詳細

プロパティ

設定項目説明
ステータス取得元ステータスを監視する範囲を選ぶセレクト。「全てのノード」「同一グループ内」「選択したノード」の3つから選ぶ
名前エディター上のノード表示名

「ステータス取得元」で「選択したノード」を選ぶと「ノードを選択...」ボタンが現れ、監視するノードを個別に指定できる。3つの選択肢の意味は次のとおり。

選択肢説明
全てのノード同じフロー（タブ）上の全ノードのステータスを監視する
同一グループ内Status ノードが置かれたグループ内のノードだけを監視する
選択したノード「ノードを選択...」ボタンで個別に選んだノードだけを監視する

出力メッセージ

{ "status": { "fill": "green", // 色: red, green, yellow, blue, grey "shape": "dot", // 形状: dot, ring "text": "connected" // テキスト }, "source": { "id": "ノードID", "type": "mqtt in", "name": "MQTT購読" } }

よくあるステータスパターン

fill（色）shape（形状）意味
greendot（塗りつぶし）正常・接続中
yellowring（輪）待機中・処理中
reddotエラー・切断
bluedot情報・アクティブ
greyring無効・停止

4. Catch ノードとの違い

ノード検知するもの発火タイミング
Complete処理完了ノードがメッセージ処理を完了したとき
Status状態変化ノードがステータスを更新したとき
Catchエラーノードがエラーを投げたとき
HTTP Request → 正常完了 → Complete
→ ステータス変化 → Status
→ エラー発生 → Catch

6. 演習問題

演習1: Complete で処理時間を計測 初級

課題: Delay ノードの処理完了を Complete ノードで検知し、開始から完了までの時間を表示してください。

💼 使いどころ: 処理の開始から完了までにかかった時間を計測する場面で使います。

成功の条件:

  • Injectボタンをクリックしてから約3秒後にデバッグサイドバーへ出力が表示される（即座には表示されない）
  • 出力の msg.payload が "経過時間: 3000ms" のような文字列になっている（数値は設定した遅延時間に近い値）
  • Debugノードのステータス欄にも経過時間が表示される
  • Delayノードへの通常出力（メイン出力）とCompleteノードからの完了通知が別々に処理されている
💡 ヒント

1. Inject ノードで msg.startTime に現在時刻を設定

2. Complete ノードで Delay の完了を検知

3. Function ノードで経過時間を計算

演習2: Status でノード状態を監視 中級

課題: Function ノードでステータスを更新し、Status ノードでその変化を検知してください。

💼 使いどころ: ノードの処理状況の変化を、別のノードで捕捉して確認する場面で使います。

成功の条件:

  • Injectボタンをクリックした直後にFunctionノードの下に黄色の「処理中」ステータスが表示される
  • 約1.5秒後にFunctionノードの下が緑の「完了」ステータスに変化する
  • デバッグサイドバーにStatusノードから msg.status オブジェクト（fill、shape、textを含む）が出力される
  • Debugノードのステータス欄にステータスのテキスト（「処理中」→「完了」）が表示される
💡 ヒント

Function 内で node.status({fill:"色", shape:"形状", text:"テキスト"}) を使用します。

演習3: 3種類の監視ノード組み合わせ 上級

課題: Complete、Status、Catch を組み合わせて、処理の成功/失敗を監視するフローを作成してください。

💼 使いどころ: 処理の成功・失敗と状態変化を、それぞれ別々に捕捉して確認する場面で使います。

成功の条件:

  • Injectボタンをクリックするたびに、FunctionノードのステータスがStatusノード経由でデバッグサイドバーに出力される
  • 処理が成功したとき（約70%の確率）は「成功」Debugに msg.payload が出力される
  • 処理が失敗したとき（約30%の確率）は「エラー」Debugに msg.error オブジェクトが出力される
  • どちらの場合でも「状態監視」のStatusノードがFunctionノードのステータス変化（実行中/成功/エラー）を検知して出力する
💡 ヒント

Function ノードで node.error() を使うとエラーを発生させ、Catch で捕捉できます。

7. まとめ

ポイント:

  • Complete: 処理完了の検知（非同期処理の監視に有効）
  • Status: ステータス変化の検知（接続状態や処理状況の監視）
  • Catch と組み合わせて監視体制を構築
  • 対象ノードの選択で監視範囲を絞り込める

注意事項:

  • すべてのノードが Complete に対応しているわけではない
  • Status は頻繁に発火する可能性があるので、必要なノードのみ監視
  • 無限ループを作らないよう注意（監視ノード自身を監視対象にしない）

8. 実務活用例

ケース1: HTTP Request の完了監視

外部API呼び出しの完了をComplete で検知し、後続処理をトリガー。

ケース2: MQTT接続状態の監視

Status ノードでMQTTブローカーへの接続状態を監視し、切断時にアラート。

ケース3: 処理時間の計測

開始時刻を記録し、Complete で完了を検知して処理時間をログ。

ケース4: バッチ処理の進捗監視

各処理ステップの Status を監視してダッシュボードに進捗を表示。
