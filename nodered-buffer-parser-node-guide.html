Node-RED buffer-parser ノードガイド

⚠️ クラウド可（パレット追加が必要） 環境とは？

このガイドで扱うノードについて

buffer-parser と buffer-maker は Node-RED の標準ノードに含まれていない追加パッケージである。パッケージ名は node-red-contrib-buffer-parser、本ガイド執筆時点の版は v3.2.2（2022-01-30 公開）。MIT ライセンスで、依存パッケージを持たない。

エディターの表示は英語のみで、日本語の訳語は用意されていない。そのため本ガイドの設定項目は「English Label（日本語訳）」の形式で示す。

  • GitHub: Steve-Mcl/node-red-contrib-buffer-parser
  • 作者: Steve-Mcl

免責： 本ガイドは上記バージョンでの動作を前提に書いている。パッケージの更新は 2022 年で止まっているため、Node-RED 本体の更新によって挙動が変わる可能性がある。導入前に最新の状況を確認してほしい。

1. 概要：何を解決するノードか

PLC やシリアル機器から届くデータは、たいてい数値の並びである。1つの温度を読むだけでも、どの位置から何バイトを取り出し、どの型として解釈し、何倍すれば実際の値になるのかを決めなければならない。バイト列そのものの成り立ちは変数ガイド Part 1 のバイナリデータとBufferで扱っている。

この変換は Function ノードでも書ける。ただし取り出す項目が増えるほどコードは長くなり、型やバイト順の取り違えを見つけにくくなる。buffer-parser は、同じ変換を表形式の設定に置き換える。

// Function ノードで書いた場合（3項目を取り出す） const buf = Buffer.from(msg.payload); msg.payload = { temperature: buf.readInt16BE(0) * 0.1, pressure: buf.readInt16BE(2) * 0.01, running: (buf[4] & 0x01) === 1 }; return msg;

buffer-parser では、同じ内容を3行の設定として書く。型はドロップダウンから選ぶため、綴りの誤りが起きない。

Type Name Offset Length scale
int16 (be) temperature 0 1 0.1
int16 (be) pressure 2 1 0.01
bool running 4 1 （表示されない）
どちらを選ぶか：

取り出す項目が1つか2つで、条件分岐も伴うなら Function ノードのほうが素直である。項目が多い、バイト順の入れ替えが要る、設定を後から見直す見込みがある、という場合に buffer-parser が効く。

2. インストール方法

Node-RED エディターの「パレットの管理」から導入する。

  1. エディター右上のメニュー（三本線）から「パレットの管理」を開く
  2. 「ノードを追加」タブを選ぶ
  3. 検索欄に node-red-contrib-buffer-parser と入力する
  4. 該当パッケージの「ノードを追加」ボタンを押す
  5. インストール後、パレットの「parser」カテゴリに buffer-parser と buffer-maker が現れる

コマンドラインから入れる場合は、Node-RED のユーザーディレクトリ（多くは ~/.node-red、Windows では %userprofile%\.node-red）で次を実行する。

npm install node-red-contrib-buffer-parser
導入は軽い：

このパッケージは依存パッケージを持たず、ネイティブビルドも伴わない。Raspberry Pi でも短時間で入り、Node.js の更新時に入れ直す必要もない。

3. 基礎知識：バイト順とワード

設定項目を読む前に、3つの言葉を押さえておく。ここが分かっていれば、設定の大半は迷わず埋められる。

エンディアン（バイトの並び順）

2バイト以上の数値をメモリに置くとき、上位バイトを先に置く方式と、下位バイトを先に置く方式がある。前者をビッグエンディアン（be）、後者をリトルエンディアン（le）と呼ぶ。

数値 253 を 2 バイトで表すと ビッグエンディアン (be) : 00 FD ← 上位が先 リトルエンディアン (le) : FD 00 ← 下位が先

同じバイト列でも、どちらとして読むかで結果が変わる。00 FD を be で読めば 253、le で読めば 64768 になる。機器の仕様書に記載があるのが本来だが、記載がない場合は両方試して意味の通る側を採用することになる。

ワードとワードスワップ

PLC の世界では、16 ビット（2バイト）を1単位として扱うことが多い。この単位をワードと呼ぶ。データが「16bit の数値の配列」として届くのは、この事情による。

ややこしいのは、バイト順とワード順が別々に入れ替わることである。32 ビットの値は2つのワードに跨るため、バイト順が合っていてもワードの順番が逆なら、値は意味をなさない。

float の 12.5 は 4 バイトで 41 48 00 00 正しい順で読む : 41 48 00 00 → 12.5 ワードの順が逆の機器なら : 00 00 41 48 → 2.34e-41（無意味な値）

buffer-parser の「Byte swap」は、この入れ替えを設定で吸収するためにある。swap16 は2バイトごと、swap32 は4バイトごと、swap64 は8バイトごとに並びを反転する。

スワップの効き方を目で見る

16bit の配列 [25185, 25699, 26213, 26727] は、そのままバイト列にすると 62 61 64 63 66 65 68 67 になる。文字として読むと badcfehg で、2文字ずつ入れ替わっている。

swap16 なし : 62 61 64 63 66 65 68 67 → "badcfehg" swap16 あり : 61 62 63 64 65 66 67 68 → "abcdefgh"

swap16 を1回かけるだけで、意図した並びに戻る。数値でも同じことが起きているため、値が桁違いにおかしいときはまずスワップを疑う。

スワップは変換より先に行われる：

Byte swap はバイト列に対して先に適用され、そのあとで各項目の型変換（le と be の解釈）が走る。この順序のため、be と le の指定だけでは直らないズレを、スワップで整えることになる。スワップは3つまで重ねて指定できる。

4. ノード構成

パッケージには向きの違う2つのノードが入っている。

buffer-parser

バイト列 → 値

受け取ったバッファや配列を、仕様に従って複数の値へ切り分ける。PLC やシリアル機器から読んだデータを扱うときに使う。

buffer-maker

値 → バイト列

複数の値を1つのバッファへ組み立てる。機器へ書き込むコマンドを作るときに使う。

設定の考え方は共通で、どちらも「項目（item）を並べた仕様」を作る点が同じである。違うのは向きだけと考えてよい。

5. 設定項目一覧

エディターの表示は英語のみのため、英語ラベルに日本語訳を添えて示す。

buffer-parser（ノード本体の設定）

設定項目 説明 既定値
Name（名前） エディター上のノード表示名。 （空）
Property（入力プロパティ） 変換元のデータが入っているプロパティ。msg / flow / global から選べる。msg.payload 以外に置いたデータも直接扱える。 msg.payload
Specification（仕様） 項目の定義をどこから得るか。spec（ここで組み立てる）を選ぶと下に項目の表が現れる。msg / flow / global を選ぶと、実行時に渡した仕様で動く。 spec（UI で組み立て）
Byte swap（バイトの入れ替え） 変換前に適用する並び替え。swap16 / swap32 / swap64 から選ぶ。欄は3つあり、順に重ねて適用される。 （なし）
Output property（出力先プロパティ） 結果を入れる msg のプロパティ名。payload 以外にすると、元の payload を残したまま結果を追加できる。 payload
Output options（出力の動作） 3つのチェックボックス。multiple results（項目ごとに別のメッセージを送る）、set topic（項目名を msg.topic にする）、fan out（項目ごとに別の出力端子から送る）。 multiple results と fan out はオフ、set topic はオン
Output（出力の形） 結果をどんな形にまとめるか。5つのモードがある。詳しくは7. 出力の5モードを参照。 key/value

項目の表（Specification が spec のとき）

取り出す値を1行ずつ定義する。行は追加、並べ替え、削除ができる。

列 説明 既定値
Type（型） この位置のデータをどう解釈するか。34 種類から選ぶ。6. データ型の一覧を参照。 int16 (be)
Name（名前） 取り出した値に付ける名前。出力のキーや msg.topic に使われる。=> を含めると入れ子になる（motor1=>power は payload.motor1.power になる）。 item1、item2 …
Length（個数） その型をいくつ続けて読むか。2 以上にすると結果は配列になる。文字列型では文字数を指す。 1
Offset（位置） 読み始める位置。単位は型によって変わる（バイト単位の型ならバイト、16bit 系ならワード）。同じ位置を何度指定してもよい。 0
Mask（マスク） 読み取った値と論理積を取る。0x7FFF で最上位ビットを落とす、といった使い方をする。16進のほか2進（0b1000000000000001）や8進も書ける。型が buffer のときは表示されない。 No mask（なし）
bit offset（ビット位置） 型が bool のときだけ現れる。バイト内の何ビット目を読むかを指す。 0
scale（倍率） 整数と小数の型のときだけ現れる。読み取った値に掛ける倍率、または式。マスクの後に適用される。 1
scale には式も書ける：

数値のほか、>>4（右に4ビットずらす）、+42（42 を足す）、/10（10 で割る）、>100（100 より大きければ true）のような式を書ける。生の値をそのまま使える形に直す用途に向く。

buffer-maker（値からバイト列を作る）

設定項目 説明 既定値
Name（名前） エディター上のノード表示名。 （空）
Specification（仕様） 項目の定義をどこから得るか。buffer-parser と同じ。 spec（UI で組み立て）
Byte swap（バイトの入れ替え） 組み立てた後のバッファに適用する並び替え。 （なし）
Output property（出力先プロパティ） できたバッファを入れる msg のプロパティ名。 payload

項目の表には Type（型）、Name（名前）、Length（個数）に加えて、値の取得元を指す欄がある。定数のほか、msg / flow / global のプロパティを指定できるため、複数の場所から集めた値を1つのバッファにまとめられる。

6. データ型の一覧

Type のドロップダウンには 34 種類が並ぶ。(le) はリトルエンディアン、(be) はビッグエンディアンを表す。

分類 選択肢 使いどころ
1バイト整数 byte / int8 / uint8 状態コード、小さなカウンタ
2バイト整数 int16 (le) / int16 (be) / uint16 (le) / uint16 (be) PLC のレジスタ値。最もよく使う
4バイト整数 int32 (le) / int32 (be) / uint32 (le) / uint32 (be) 積算値、大きなカウンタ
8バイト整数 bigint64 (le) / bigint64 (be) / biguint64 (le) / biguint64 (be) 桁の大きい積算値
小数 float (le) / float (be) / double (le) / double (be) 計測値をそのまま小数で持つ機器
ビット 8bit / 16bit (le) / 16bit (be) / bool 接点のオンオフ、警報フラグ
BCD bcd (le) / bcd (be) 表示器や旧型機器の数値
文字列 string / hex / ascii / utf8 / utf16 (le) / ucs2 / latin1 / binary 型番、ロット番号などの文字データ
そのまま buffer 切り出しだけ行い、解釈は後段に任せる
BCD は見た目どおりの数値になる型：

BCD（2進化10進数）は、16進で 0x1234 と書かれた値を 1234 として読む方式である。ふつうの整数として読むと 4660 になり、桁がまるで違う。数値表示器や旧型の PLC でよく使われるため、値が「10進で見たときの見た目」と合わない場合はこの型を疑う。

7. 出力の5モード

Output の選択によって、結果の形が変わる。項目に temperature と pressure の2つを定義した場合で比べる。

選択肢 結果の形 向いている用途
key/value { temperature: 25.3, pressure: 1.01 } そのままダッシュボードやデータベースへ送る
key/object 名前ごとに value と項目の定義を含むオブジェクト どんな設定で読んだ値かを後段でも参照したい
values only (array) [25.3, 1.01] 値の並びだけあればよい場合
array (of objects) 各項目をオブジェクトにした配列 項目数が可変で、順に処理したい
buffer 項目の切り分けをせず、バッファをそのまま返す スワップだけ適用したい

「Output options」の multiple results をオンにすると、1つのメッセージにまとめるのではなく、項目ごとに別々のメッセージが流れる。set topic をあわせてオンにすると、項目名が msg.topic に入るため、そのまま MQTT へ送るトピック付きのメッセージになる。

fan out は出力端子が増える：

fan out をオンにすると、項目ごとに別々の出力端子が生えて、それぞれ別の配線へ送れる。項目の数だけ端子が増えるため、項目を足したときは配線の付け直しが要る。

8. 実用的な使用パターン

パターン1：PLC の 16bit 配列から測定値を取り出す

MODBUS のノードは、読み取った結果を 16bit の数値の配列として渡す。この配列をそのまま buffer-parser の入力にできる。

MODBUS Read → buffer-parser → Debug

温度がレジスタの先頭に 10 倍の整数で入っている場合、次のように設定する。生の値 253 に scale の 0.1 が掛かり、25.3 になる。

Type Name Offset Length scale
int16 (be) temperature 0 1 0.1

アドレスの数え方や MODBUS 側の設定はMODBUS ノードガイドで扱っている。

パターン2：値が桁違いのときスワップで直す

読めた値が意味をなさないときは、型の le と be を入れ替える前に Byte swap を試す。前述のとおりスワップは型変換より先に適用されるため、le と be の切り替えだけでは直らないズレがある。

次の順序で進めると原因にたどり着きやすい。

  1. Output を buffer にして、生のバイト列を Debug で確認する
  2. 期待する値の並びと見比べて、2バイト単位で入れ替わっていれば swap16 を入れる
  3. 32bit の値だけおかしいなら、ワードの順が逆なので swap32 を試す
  4. それでも合わなければ、型の le と be を入れ替える

パターン3：ビット単位の状態を取り出す

1つのワードに複数の接点状態が詰まっている場合、bool 型と bit offset を使って1ビットずつ取り出す。同じ Offset を何度指定してもよい。

Type Name Offset bit offset
bool running 0 0
bool warning 0 1
bool fault 0 2

パターン4：値をバイト列に組み立てて機器へ送る

buffer-maker は逆向きの変換を担う。複数のプロパティに散らばった値を集めて、1つのバッファにまとめられる。

Inject → buffer-maker → TCP Out

組み立てた結果が正しいかは、buffer-parser を後ろに繋いで読み直すと確かめられる。公式サンプルもこの構成になっている。

10. 演習問題

演習1：温度と湿度を取り出す初級

16bit の配列 [253, 604] が届く。先頭が温度（10 倍の整数）、次が湿度（10 倍の整数）である。buffer-parser で { temperature: 25.3, humidity: 60.4 } の形にせよ。

ヒント

Output は key/value、型は int16 (be)、Offset は 0 と 1、scale は 0.1 を使う。Offset の単位は 16bit 系の型ではワード単位である。

演習2：警報ビットを取り出す中級

1バイトの値 5（2進で 00000101）が届く。ビット0を running、ビット1を warning、ビット2を fault として取り出し、それぞれ true と false で受け取れ。

ヒント

型は bool、Offset はすべて 0 のままで、bit offset を 0・1・2 と変える。結果は running が true、warning が false、fault が true になる。

演習3：値を組み立てて読み直す上級

buffer-maker で、温度 25.3 を 10 倍した整数（253）と、状態フラグ 1 を含むバッファを作れ。そのうえで buffer-parser を後ろに繋ぎ、元の値に戻ることを確認せよ。

ヒント

buffer-maker 側で int16 (be) を2つ並べる。読み直す側は同じ型と同じ順序で定義し、温度には scale 0.1 を指定する。公式サンプルの buffer-maker の例が、そのままこの構成になっている。

11. まとめ

要点：
  • buffer-parser はバイト列から値を取り出し、buffer-maker は値からバイト列を作る
  • 設定は「項目を並べた表」で、1行が1つの取り出しに対応する
  • Byte swap は型変換より先に適用される。値が桁違いのときはまずここを疑う
  • scale はマスクの後に適用される。倍率のほか式も書ける
  • 出力は5つの形から選べる。MQTT へ流すなら multiple results と set topic の組み合わせが使いやすい

12. トラブルシューティング

症状 原因 対処
読み込んだフローが「不明なノード」になる パッケージが入っていない パレットの管理から node-red-contrib-buffer-parser を入れる
値が桁違いに大きい、または小さい バイト順かワード順が合っていない Byte swap に swap16 を入れて試す。32bit の値だけおかしいなら swap32
正の値のはずが負になる 符号ありの型で読んでいる int16 ではなく uint16 を選ぶ
10進で見た表示と値が合わない BCD のデータを整数として読んでいる 型を bcd (be) または bcd (le) に変える
小数点の位置がずれる scale を指定していない 機器の仕様で 10 倍や 100 倍になっている値に、0.1 や 0.01 を指定する
scale の欄が現れない 型が整数と小数以外になっている scale は int8 / uint8 / int16 系 / int32 系 / float / double のときだけ表示される
bit offset の欄が現れない 型が bool になっていない 型を bool に変えると現れる
出力端子の数が合わない fan out がオンで、項目数と端子数がずれている 項目を増減したあとは配線を付け直す
元の payload が消える Output property が payload のまま Output property を別の名前にすると、元の payload を残せる
