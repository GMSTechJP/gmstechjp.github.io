Node-RED 正規表現ガイド

☁️ クラウドOK 環境とは？

正規表現は、文字列の「形」を書き表すための記法です。「末尾が .csv」「先頭が error」「数字が1つ以上続く」のような条件を、短い記号の並びで書けます。Node-RED では、switch ノードの条件、change ノードの置換、JSONata 式、function ノードの JavaScript で使います。

このガイドの目標は、サイトのサンプルフローや演習の解答例に出てくる正規表現を読めて、少し直せるようになることです。扱う記号は、サイトに実際に出てくるものに絞っています。扱わない記号は、まとめで外部の資料を案内します。

前提知識： switch ノードガイドと change ノードガイドの内容を把握している読者を想定しています。JSONata と function ノードは、使う箇所だけ読めば足ります。

1. 正規表現とは

「含む」では足りない場面

フォルダに届いたファイルのうち、CSV だけを処理したいとします。ファイル名に .csv を含むかどうかで調べると、data.csv.bak（CSV の控え）まで CSV として扱ってしまいます。調べたいのは「含むかどうか」ではなく、「末尾が .csv かどうか」です。

正規表現では、この条件を \.csv$ と書きます。\. がピリオド、csv がその3文字、$ が「ここで文字列が終わる」という位置を表します。

ファイル名 .csv を含む 正規表現 \.csv$
report.csv 当てはまる 一致する
data.csv.bak 当てはまる（意図と違う） 一致しない
memo.txt 当てはまらない 一致しない

正規表現に書いた形をパターン、文字列がその形に当てはまることを「一致する」（マッチする）と呼びます。

Node-RED で正規表現を書く場所

正規表現を書く場所は4つあります。記号の意味はどこでも同じですが、パターンの囲み方と、大文字と小文字の扱い方が場所ごとに違います。違いはセクション 4でまとめます。

場所 何に使うか 書き方の例
switch ノードの条件「正規表現にマッチ」 文字列の形で、メッセージを振り分ける \.csv$
change ノードの「値の置換」 形に当てはまる部分を、別の文字列に置き換える \s+
JSONata 式の $contains、$replace、$match、$split 式の中で、調べる、置き換える、取り出す、区切る $replace(payload, /\.csv$/, ".json")
function ノードの JavaScript コードの中で、調べる、置き換える、取り出す、区切る text.replace(/-/g, "")

2. 記号の読み方

記号でない文字は、その文字そのもの

パターン csv は、「c、s、v がこの順に並んでいる」という形を表します。位置を指定しなければ、文字列のどこにあっても一致します。csv は report.csv にも、csv-tool にも、mycsvfile にも一致します。

大文字と小文字は、何も指定しなければ区別します。csv は REPORT.CSV に一致しません。区別をやめる方法は書く場所ごとに違うので、セクション 4で説明します。

位置を表す記号

記号 意味 例 一致する 一致しない
^ 文字列の先頭 ^error error: timeout No error found
$ 文字列の末尾 csv$ report.csv data.csv.bak

^ と $ で両側をはさむと、「文字列の全体がこの形」という条件になります。^ok$ は ok だけに一致し、ok! や look には一致しません。

文字の種類を表す記号

記号 意味 例 一致する 一致しない
. どの文字でもよい1文字（改行を除く） a.c abc、a-c ac
\. ピリオドそのもの \.csv$ report.csv report_csv
\d 数字1文字（0〜9） \d\d 42、line12 line7
\s 空白1文字（スペース、タブ、改行、全角スペース） a\sb a b ab
[ ] 中に並べた文字のどれか1文字 [/:] 10:30、11/27 10-30

[ ] の中では、- で範囲を書けます。[0-9] は数字1文字（\d と同じ）、[A-Z] は大文字のアルファベット1文字、[0-9a-f] は数字か a〜f のどれか1文字です。

ピリオドは \. と書く：

. は「どの文字でもよい1文字」なので、.csv$ は report_csv や mycsv にも一致します。拡張子のピリオドを調べるときは、\ を前に置いて \. と書きます。

このガイドで扱う記号の文字（.、^、$、|、(、)、?、+、*、[、]、\）は、どれも前に \ を置くと、その文字そのものを表します。

繰り返しを表す記号

次の3つは、直前の1文字（または ( ) でまとめた部分）が何回続くかを表します。

記号 意味 例 一致する 一致しない
? あってもなくてもよい（0回か1回） jpe?g jpg、jpeg jpag
+ 1回以上続く ^\d+$ 7、2026 12a、空の文字列
* 0回以上続く（無くてもよい） ^ab*c$ ac、abc、abbc adc

.* は「どの文字が何文字あってもよい」という意味で、よく使われます（改行は含みません）。^error.*timeout$ は、error で始まり timeout で終わる文字列に一致します。

「または」と、まとめる記号

記号 意味 例 一致する 一致しない
| または png|gif logo.png、anime.gif photo.jpg
( ) ひとまとまりにする \.(png|gif)$ logo.png、anime.gif png.txt、logo.png.bak

| は、( ) で囲まないと、パターン全体を左右に分けます。\.png|gif$ は「.png を含む」または「末尾が gif」という意味になり、logo.png.bak にも一致します。「ピリオドのあとに png か gif が来て、そこで終わる」と書くには、\.(png|gif)$ のように ( ) で「または」の範囲を区切ります。

( ) には、もう1つ役割があります。JSONata や JavaScript では、( ) で囲んだ部分に一致した文字列を、あとから取り出せます。使い方はJSONata の説明で示します。

3. 1つの例を読み解く

FTP・SFTP ガイドの演習に、届いたファイルが画像かどうかを調べる次のパターンが出てきます。

\.(jpe?g|png|gif)$

左から順に、部品に分けて読みます。

部品 意味
\. ピリオドそのもの
( … ) 中の3つのうち、どれか1つ
jpe?g jp、あってもなくてもよい e、g。つまり jpg か jpeg
|png または png
|gif または gif
$ ここで文字列が終わる

まとめると、「ピリオドのあとに jpg、jpeg、png、gif のどれかが来て、そこで終わる」という形です。いくつかのファイル名で確かめます。

ファイル名 結果 理由
photo.jpg 一致する 末尾が .jpg
photo.jpeg 一致する e? が e に当たる
logo.png 一致する 末尾が .png
photo.jpg.bak 一致しない .jpg のあとに文字が続き、$ に合わない
jpg.txt 一致しない jpg の前にピリオドが無い
photo.JPG 一致しない 大文字と小文字を区別する。区別をやめれば一致する

カメラは photo.JPG のように拡張子を大文字で付けることがあります。FTP・SFTP ガイドの解答例は、switch ノードの「大文字、小文字を区別しない」をオンにして、大文字の拡張子も画像として扱っています。

4. 書く場所ごとの違い

同じパターンでも、書く場所によって囲み方と指定のしかたが変わります。ここを取り違えると、パターンが正しくても一致しません。

場所 パターンの書き方 大文字と小文字を区別しない 一致する箇所が複数あるとき
switch「正規表現にマッチ」 欄にパターンだけを書く
\.csv$		 「大文字、小文字を区別しない」をオンにする 一致するかどうかだけを調べる
change「値の置換」 「検索する文字列」の型を「正規表現」にして、パターンだけを書く
\s+		 指定できない（区別する） すべて置き換える
JSONata / で囲む
/\.csv$/		 うしろに i を付ける
/\.csv$/i		 $replace はすべて置き換え、$match はすべて返す
JavaScript（function） / で囲む
/\.csv$/		 うしろに i を付ける
/\.csv$/i		 replace と match は、うしろに g を付けたときだけ、すべてが対象になる。split は、g が無くてもすべての箇所で区切る

/ のうしろに付ける i や g をフラグと呼びます。i は「大文字と小文字を区別しない」、g は「一致したすべてを対象にする」という指定です。2つを同時に付けるときは、/-/gi のように並べます。

switch ノード

条件の種類で「正規表現にマッチ」を選ぶと、パターンを書く欄と「大文字、小文字を区別しない」のチェックボックスが出ます。

  • 欄にはパターンだけを書きます。/ で囲みません。/\.csv$/ と書くと、/ という文字も探す対象になり、一致しなくなります
  • 調べるのは、文字列のどこかがパターンに一致するかどうかです。全体が一致することを求めるときは、^ と $ ではさみます
  • 調べる値が数値のときは、文字列に直してから調べます。msg.payload が数値の 404 なら、^4 に一致します
  • パターンに誤りがあると（括弧の閉じ忘れなど）、メッセージが届いた時点でエラーになり、どの出力にも送られません。debug サイドバーに、Invalid regular expression を含むエラーが出ます

change ノード

ルールの種類で「値の置換」を選び、「検索する文字列」の欄の左の型を「正規表現」に切り替えます。型が「文字列」のままだと、\s+ は記号として働かず、\s+ という3文字そのものを探します。

  • 欄にはパターンだけを書きます。/ で囲まず、i や g も付けません
  • 一致したところは、すべて置き換わります。1つ目だけを置き換える指定はありません
  • 大文字と小文字は区別します。区別をやめる指定はありません。両方に一致させるには、[Cc][Ss][Vv] のように1文字ずつ [ ] で書くか、JSONata の $replace と i を使います
  • 置き換わるのは、プロパティの値が文字列のときだけです。値が数値のときは、何も変わりません
  • パターンに誤りがあると、デプロイした時点で、debug サイドバーに「操作対象のプロパティが不正」で始まるエラーが出ます（Node-RED が英語で動いているときは Invalid 'from' property）。メッセージが届く前に分かります

JSONata 式

JSONata では、パターンを / で囲んで書きます。文字列を受け取る次の4つの関数に、文字列の代わりに渡せます。関数の基本は JSONata式ガイドにあります。

関数 すること 例（payload が REPORT.CSV のとき） 結果
$contains 一致するかどうかを調べる $contains(payload, /\.csv$/i) true
$replace 一致したところを、すべて置き換える $replace(payload, /\.csv$/i, ".json") "REPORT.json"
$match 一致したところを取り出す $match(payload, /\.csv$/i).match ".CSV"
$split 一致したところで区切って、配列にする $split(payload, /\./) ["REPORT", "CSV"]
  • 付けられるフラグは i と m です（m は、複数行の文字列で、^ と $ を各行の先頭と末尾にも一致させる指定）。g は付けられません（式のエラーになります）。$replace は、g が無くてもすべてを置き換えます
  • * や ? だけでできたパターン（\d* など）は、何もない位置（長さ 0）にも一致します。$replace、$match、$split は、長さ 0 の一致が起きると、エラーになることがあります。\d+ のように、1文字以上に一致する形で書きます

$match は、一致したところごとに、次の3つを持つオブジェクトを返します。一致が1つならオブジェクトが1つ、複数ならその配列、一致が無ければ何も返しません。

項目 内容
match 一致した文字列
index 一致した位置（先頭が 0）
groups パターンの ( ) で囲んだ部分に一致した文字列の配列。( ) の順に並ぶ

groups を使うと、文字列の一部を取り出せます。payload が line1_20261127.csv のとき、次の式は ["1", "20261127"] を返します。1つ目の ( ) がライン番号、2つ目の ( ) が日付に当たります。

$match(payload, /^line(\d+)_(\d+)\.csv$/).groups

JavaScript（function ノード）

JavaScript でも、パターンを / で囲んで書きます。文字列のメソッドに渡すか、パターンの test() を呼びます。text が 090-1234-5678 のときの結果を示します。

書き方 すること 結果
/^[0-9-]+$/.test(text) 一致するかどうかを調べる true
text.replace(/-/g, "") 一致したすべてを置き換える "09012345678"
text.replace(/-/, "") 1つ目だけを置き換える "0901234-5678"
text.match(/\d+/g) 一致したすべてを配列で取り出す ["090", "1234", "5678"]
text.split(/-/) 一致したところで区切って、配列にする ["090", "1234", "5678"]
JavaScript の replace は、g が無いと1つ目だけ：

change ノードと JSONata の $replace は、何も指定しなくてもすべてを置き換えます。JavaScript の replace だけは、g を付けないと1つ目で止まります。置き換え漏れがあるときは、g を付け忘れていないかを確かめます。

パターンの中で / そのものを探すときは、\/ と書きます。/ がパターンの終わりと区別できなくなるためです。"2026/11/27".replace(/\//g, "-") は "2026-11-27" になります。switch と change の欄では / で囲まないので、/ はそのまま書けます。

5. フローの JSON での見え方

ガイドのフローの JSON を開くと、パターンの \ が2つ並んでいます。

見る場所 表示
エディターの switch の欄 \.csv$
フローの JSON "v": "\\.csv$"

これは誤りではありません。JSON では、文字列の中に \ という文字を1つ書くとき、\\ と2つ並べる決まりがあります。フローを読み込むと、エディターの欄には \ が1つの \.csv$ が出ます。

欄に入力するときは \ を1つ：

エディターの欄に自分で入力するときは、\.csv$ のように \ を1つだけ書きます。JSON の見た目をまねて \\.csv$ と入力すると、「\ という文字のあとに、どれか1文字と csv が続く」という別のパターンになり、report.csv に一致しません。

JSONata の式と function のコードも、フローの JSON では同じように \ が2つになります。エディターで開けば、\ は1つです。

6. 正規表現と混同しやすいもの

同じ記号を、正規表現とは別の意味で使う書き方が2つあります。どちらも正規表現ではないので、ここまでの記号の読み方は当てはまりません。

書き方 出てくる場所 その場所での意味 正規表現での意味
*.csv の * ターミナルのコマンド（ls *.csv など） どんな文字列でもよい 直前の1文字が0回以上続く
sensor/+/temp の + MQTT のトピック 1階層分の、どんな文字列でもよい 直前の1文字が1回以上続く
  • ターミナルの *.csv は、正規表現では \.csv$ と書きます。*.csv をそのまま switch の欄に書くと、* の前に繰り返す文字が無いため、エラーになります
  • MQTT のトピックの + と # は、ワイルドカードと呼ばれる MQTT の決まりです。使い方は MQTT ガイドにあります

フローの読み解き

フローは4つの部分に分かれていて、それぞれの先頭にコメントノードがあります。上の図は1つ目の部分です。残りの3つは、どれも inject、処理するノード、debug が1つずつ横に並びます。

コメントノード ノードの並び 正規表現を書いている場所
1. switch で振り分ける（正規表現にマッチ） inject 4つ → switch「拡張子で振り分け」→ debug「CSV」「画像」「その他」 switch の条件
2. change で置き換える（値の置換） inject「空白の多い文字列を送る」→ change「続いた空白を1つにする」→ debug「置き換えた結果」 change の「検索する文字列」
3. JSONata で調べる、置き換える inject「REPORT.CSV を送る」→ change「JSONata で調べる」→ debug「JSONata の結果」 change の「代入する値」の JSONata 式
4. function（JavaScript）で使う inject「090-1234-5678 を送る」→ function「JavaScript で置き換える」→ debug「JavaScript の結果」 function のコード

1. switch で振り分ける

switch「拡張子で振り分け」は、msg.payload（ファイル名）を上から順に3つの条件で調べます。条件の下の選択は「全ての条件を適用」のままです。1つ目と2つ目のパターンに同時に一致するファイル名は無く、「その他」はどの条件にも当てはまらなかったときだけ出るので、1つのファイル名が2つの debug に出ることはありません。

出力 条件 大文字、小文字を区別しない つながる debug
1 正規表現にマッチ \.csv$ オフ CSV
2 正規表現にマッチ \.(jpe?g|png|gif)$ オン 画像
3 その他 （欄なし） その他

4つの inject を押すと、次の debug に出ます。

押す inject 出る debug 理由
report.csv を送る CSV 末尾が .csv
photo.JPG を送る 画像 2つ目の条件は大文字と小文字を区別しないので、.JPG も jpe?g に一致する
data.csv.bak を送る その他 .csv のあとに .bak が続き、$ に合わない
memo.txt を送る その他 どちらのパターンにも一致しない

1つ目の条件は大文字と小文字を区別するので、inject のファイル名を REPORT.CSV に書き換えて押すと、「その他」に出ます。条件の「大文字、小文字を区別しない」をオンにしてデプロイすると、「CSV」に出るようになります。

2. change で置き換える

inject は、空白がいくつも続く文字列 温度 25.5 ℃ を送ります。change「続いた空白を1つにする」は「値の置換」のルールで、「検索する文字列」が正規表現の \s+、「置換後の文字列」がスペース1つです。\s+ は「空白が1つ以上続いたところ」なので、続いた空白がそれぞれスペース1つになり、debug「置き換えた結果」に 温度 25.5 ℃ が出ます。空白が続く箇所は2つありますが、change はすべてを置き換えるので、両方とも1つになります。

3. JSONata で調べる、置き換える

inject は REPORT.CSV を送ります。change「JSONata で調べる」は、msg.payload に次の JSONata 式の結果を代入します。

{ "元の名前": payload, "CSVか": $contains(payload, /\.csv$/i), "JSONの名前": $replace(payload, /\.csv$/i, ".json") }

どちらのパターンにも i を付けているので、大文字の .CSV に一致します。debug「JSONata の結果」には、次のオブジェクトが出ます。

項目 値 意味
元の名前 "REPORT.CSV" 届いた文字列
CSVか true 末尾が .csv（大文字でもよい）かどうか
JSONの名前 "REPORT.json" 末尾の .csv を .json に置き換えた名前

式の i を2つとも消してデプロイすると、「CSVか」が false になり、「JSONの名前」は REPORT.CSV のまま変わりません。

4. function（JavaScript）で使う

inject は 090-1234-5678 を送ります。function「JavaScript で置き換える」は、同じ文字列に3つの処理をして、結果をオブジェクトにまとめます。function ノードを使っているのは、JavaScript での書き方を示すためです。

項目 コード 値
すべて置き換え text.replace(/-/g, "") "09012345678"
1つ目だけ text.replace(/-/, "") "0901234-5678"
数字とハイフンだけか /^[0-9-]+$/.test(text) true

1つ目と2つ目の違いは g の有無だけです。3つ目の ^[0-9-]+$ は、「先頭から末尾まで、数字かハイフンが1文字以上続く」という形です。[ ] の中で - そのものを表すときは、[0-9-] のように末尾に置きます。

パターンを試すには

このフローは、自分のパターンを試す場所としても使えます。1つ目の部分の inject の文字列と、switch のパターンを書き換えてデプロイし、ボタンを押すと、一致するかどうかが debug の出る先で分かります。一致する例と一致しない例の両方を inject に用意しておくと、パターンが広すぎる（余計なものまで一致する）場合にも気づけます。

( $m := $match(payload, /^line(\d+)_(\d+)\.csv$/i); { "ライン": $number($m.groups[0]), "日付": $m.groups[1] } )

1行目で $match の結果を変数 $m に入れ、そのあとで groups の1つ目と2つ目を取り出しています。switch と JSONata で同じパターンを使っていますが、JSONata の方は / で囲み、取り出す部分に ( ) を足し、i を付けています。

9. うまく一致しないとき

症状 原因 対処
photo.JPG のような大文字の文字列が一致しない 大文字と小文字を区別している switch は「大文字、小文字を区別しない」をオンにする。JSONata と JavaScript は i を付ける。change は指定できないので、[Jj][Pp][Gg] のように書くか、JSONata の $replace を使う
data.csv.bak のような、余計な文字列まで一致する 位置を指定していない 末尾を調べるなら $、先頭を調べるなら ^ を付ける
report_csv のような、ピリオドの無い文字列まで一致する . が「どの文字でもよい1文字」として働いている ピリオドは \. と書く
switch や change で、正しいはずのパターンが一致しない 欄に /\.csv$/ や /csv/i のように、/ やフラグまで書いている 欄にはパターンだけを書く。/ とフラグは、JSONata と JavaScript での書き方
change で、記号が働かず何も置き換わらない 「検索する文字列」の型が「文字列」のままになっている 型を「正規表現」に切り替える
自分で入力したパターンだけ一致しない フローの JSON をまねて、欄に \\.csv$ と入力している 欄では \ を1つにする（セクション 5）
function で、1つ目しか置き換わらない replace のパターンに g が無い /-/g のように g を付ける
switch で、debug に Invalid regular expression を含むエラーが出る パターンの書き方に誤りがある。Unterminated group は括弧の閉じ忘れ、Nothing to repeat は * や + の前に繰り返す文字が無い エラーの文に出ているパターンを見直す。*.csv のような書き方は正規表現ではない（セクション 6）
JSONata の式で、/-/g と書くとエラーになる JSONata のパターンには g を付けられない g を消す。$replace は g が無くてもすべてを置き換える
JSONata で Regular expression matches zero length string というエラーが出る パターンが、何もない位置（長さ 0）に一致している * を + にするなど、1文字以上に一致する形に直す

10. まとめ

正規表現の要点：
  • 正規表現は、文字列の形を書き表す記法。「末尾が .csv」は \.csv$ と書く
  • 位置は ^（先頭）と $（末尾）で指定する。指定しなければ、文字列のどこにあっても一致する
  • ピリオドそのものは \. と書く。. だけだと、ピリオド以外の文字にも一致する
  • switch と change の欄には、パターンだけを書く。JSONata と JavaScript では / で囲む
  • 大文字と小文字を区別しない指定は、switch はチェックボックス、JSONata と JavaScript は i。change には無い
  • JavaScript の replace は、g を付けないと1つ目だけを置き換える
  • フローの JSON では \ が \\ と書かれる。エディターの欄では \ は1つ
