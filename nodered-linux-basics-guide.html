1. なぜ Node-RED 利用者が Linux を知る必要があるのか

Node-RED はブラウザだけで操作できるので、Linux を知らなくてもフローは作れます。それでも Linux の知識が必要になるのは、次のような場面です。

場面 必要になる知識
インストール・追加ノードの導入 パッケージ管理（apt）、権限（sudo）、ホームディレクトリの意味
電源を入れたら自動で Node-RED を起動したい サービスと systemctl、自動起動の設定
設定を変更したい（settings.js、ポート番号） ファイルの場所（~/.node-red）、テキストエディタ、ファイルの権限
Exec ノードでコマンドを実行したい コマンドの書式、実行ユーザー、パスの通し方
File / Watch ノードでファイルを読み書きしたい 絶対パスの書き方、読み書き権限
動かなくなった原因を調べたい ログの見方（journalctl）、プロセスの確認、ディスク容量の確認

言い換えると、フローの中だけで完結する作業に Linux は要らず、フローの外側（起動・設定・ファイル・トラブル対応）に踏み出した瞬間に必要になるということです。このシリーズは、その外側だけを扱います。

ラズパイを持っていなくても読む価値はあります

ここで説明する内容は Linux 全般に共通します。クラウド上の Node-RED が動いているのも Linux ですし、Windows でも WSL や Docker を使えば同じ世界に触れることになります。

2. OS は何をしている道具なのか

OS（オペレーティングシステム）は、ハードウェアとアプリケーションの間に立つ仲介役です。もし OS がなければ、Node-RED は「SD カードのどの位置にデータを書き込むか」「ネットワークチップにどの信号を送るか」まで自分で面倒を見る必要があります。OS はその面倒を肩代わりし、アプリには「ファイルに書き込む」「通信する」という簡単な形で見せてくれます。

OS の主な仕事は次の5つです。

仕事 内容 Node-RED での現れ方
CPU の割り振り 複数のプログラムに CPU の時間を細かく分け与え、同時に動いているように見せる Node-RED と他のソフトが同時に動く。重い処理を書くと全体が遅くなる
メモリの管理 各プログラムに作業領域を割り当て、互いに侵食しないよう隔離する メモリが尽きると Node-RED が強制終了される
ファイルの管理 ストレージ上のデータに名前と場所を与え、読み書きを仲介する フローが flows.json というファイルとして保存される
機器の操作 USB、ネットワーク、GPIO などの装置を、統一された方法で扱えるようにする GPIO ノードやシリアルノードが機器にアクセスできる
利用者の管理 誰がどのファイルを読み書きできるかを制御する 権限のないファイルを読もうとするとエラーになる

この5つは Windows でも macOS でも同じです。違うのは「その仕事のやり方」と「利用者への見せ方」だけです。

3. Linux の構造：カーネル・シェル・アプリ

Linux は層構造になっています。下に行くほどハードウェアに近く、上に行くほど人間に近い層です。

アプリケーションNode-RED、ブラウザ、Python、テキストエディタ
▲ ▼
シェル（bash）／デスクトップ画面人間の入力を、アプリやカーネルへの指示に変換する
▲ ▼
ライブラリ・システムサービス共通部品と、常駐して働くプログラム（systemd など）
▲ ▼
カーネル（Linux 本体）CPU・メモリ・ファイル・機器を直接管理する中核
▲ ▼
ハードウェアCPU、メモリ、SD カード、USB、ネットワーク、GPIO ピン

カーネル：本来「Linux」と呼ばれているもの

厳密には、「Linux」とはこのカーネルの部分だけを指す言葉です。カーネルはハードウェアを直接管理し、アプリからの「ファイルを開きたい」「通信したい」という要求を受け付けます。アプリが直接ハードウェアを触ることはできず、必ずカーネルを通します。この仕切りがあるおかげで、1つのアプリが暴走してもシステム全体は生き残れます。

使用中のカーネルのバージョンは uname -r で確認できます。

シェル：コマンドを受け付ける係

シェルは、人間が打ち込んだコマンドを解釈して実行する専用のプログラムです。「黒い画面」に文字を打つとき、その文字を最初に読んでいるのはシェルです。Raspberry Pi OS の標準シェルは bash（バッシュ）です。

混同しやすいのがターミナルとの違いです。ターミナルは文字を表示して入力を受け取る「窓」であり、その窓の中で動いてコマンドを実行しているのがシェルです。窓（ターミナル）と中の人（シェル）は別物、と考えると整理できます。

GUI は必須ではない

Windows ではデスクトップ画面が OS と一体ですが、Linux では画面表示は上に乗せた別のソフトです。そのため、モニタもキーボードも繋がずネットワーク越しに操作するヘッドレス運用が普通にできます。Node-RED をラズパイで運用する場合は、この形が最も一般的です。デスクトップなしの Raspberry Pi OS Lite が用意されているのもこのためです。

4. Raspberry Pi OS の正体（Debian との関係）

カーネル単体では何もできないので、シェル、コマンド群、設定ファイル、インストーラなどを一式にまとめたものが配布されます。これをディストリビューション（配布物）と呼びます。Debian、Ubuntu、Red Hat Enterprise Linux などは、すべてこのディストリビューションの名前です。

Raspberry Pi OS は、Debian（デビアン）というディストリビューションをラズベリーパイ向けに調整したものです。したがって、インターネットで「Debian の設定方法」「Ubuntu のコマンド」として書かれている情報の多くは、そのまま通用します（Ubuntu も Debian の派生です）。

バージョンの呼び名

Debian は各バージョンにコードネームを付けており、Raspberry Pi OS もそれをそのまま引き継いでいます。ネット上の記事は「Bookworm では〜」のようにコードネームで書かれることが多いので、対応を知っておくと調べ物が楽になります。

コードネーム Debian 位置づけと主な特徴
trixie（トリクシー） Debian 13 現在の標準。設定画面が「Control Centre」に統合された。2026年4月以降の新規インストールでは sudo にパスワードが必要（後述）
bookworm（ブックワーム） Debian 12 1つ前の版。まだ広く使われている。画面表示が Wayland 方式になり、ネットワーク管理が NetworkManager に変わった版
bullseye（ブルズアイ） Debian 11 さらに古い版。ネットワーク設定は dhcpcd で、起動用フォルダの位置も異なる（②ディレクトリ構成ガイドで解説）

自分の環境がどれなのかは、次のコマンドで確認できます。

cat /etc/os-release

表示された VERSION_CODENAME= の行がコードネームです。

32bit 版と 64bit 版があります

Raspberry Pi OS には 32bit 版（armhf）と 64bit 版（arm64）があり、Pi 3 以降なら 64bit 版を選べます。Node-RED を使う分にはどちらでも動きますが、追加ノードによっては 64bit 版しか対応していないことがあります。確認は uname -m で、aarch64 と表示されれば 64bit 版です。

5. 「すべてはファイル」という考え方

Linux を理解するうえで最も効く考え方が、「すべてはファイルとして扱う」という設計思想です。文書や画像はもちろん、次のようなものまでファイルの形で見えます。

見え方（ファイル名） 実体
/dev/ttyUSB0 USB 接続のシリアル変換器。ここに書き込むと機器にデータが送られる
/dev/gpiochip0 ラズパイの GPIO ピン群
/proc/cpuinfo CPU の情報。ディスク上には実在せず、読んだ瞬間にカーネルが内容を作る
/sys/class/thermal/thermal_zone0/temp CPU の温度（1000倍の値）。読み出すたびに現在値が入る
/dev/null 捨て場。ここに書いたデータは消える。出力を捨てたいときに使う

この思想の実利は大きく、ファイルを読み書きする方法さえ覚えれば、機器の操作や情報の取得も同じやり方でできることを意味します。実際、Node-RED の File ノードで /sys/class/thermal/thermal_zone0/temp を読むだけで CPU 温度が取れます。専用のノードは要りません。

💻 試してみる：CPU 温度をファイルから読む

ターミナルで次を実行します。

cat /sys/class/thermal/thermal_zone0/temp

48312 のような数字が出れば成功です。これは1000倍された値なので、実際の温度は 48.312 ℃ です。Node-RED でやるなら、File in ノードでこのパスを指定し、Function ノードで msg.payload = Number(msg.payload) / 1000; とすれば温度になります。

6. ユーザーと権限：root と sudo

Linux は元々、1台のコンピュータを複数人で共有する前提で作られています。ラズパイを1人で使う場合でもこの仕組みは生きていて、権限エラーの多くはここに原因があります。

root は特別扱いの管理者

root（ルート）は、すべての操作が許された管理者ユーザーです。システムのどのファイルも書き換えられる代わりに、間違えれば OS を壊すこともできます。そのため普段は一般ユーザーとして作業し、管理者権限が必要なときだけ sudo を頭に付けて、そのコマンド1回だけを root として実行します。

apt install git # 権限がなく失敗する sudo apt install git # このコマンドだけ管理者として実行

sudo でパスワードを聞かれるようになりました

従来の Raspberry Pi OS は sudo にパスワードが不要でしたが、2026年4月13日版以降の新規インストールでは、セキュリティ強化のためパスワードの入力が求められます。設定を変えた覚えがないのに聞かれるのはこのためです（既存環境をアップデートした場合は従来どおり）。入力するのは、そのユーザー自身のログインパスワードです。パスワードなしに戻したい場合は sudo raspi-config または Control Centre から変更できます。

なお、パスワード入力中は画面に * すら表示されません。打てていないように見えますが、そのまま入力して Enter を押してください。

ファイルには「所有者」と「許可」が付いている

すべてのファイルとフォルダには、所有者（ユーザー）、所属グループ、そして「誰に何を許すか」の情報が付いています。ls -l で表示される先頭の記号がそれです。

-rw-r--r-- 1 pi pi 2048 Aug 1 10:23 flows.json drwxr-xr-x 2 root root 4096 Jul 20 08:00 nodes

先頭10文字の読み方は次のとおりです。

位置 例 意味
1文字目 - / d - は通常ファイル、d はディレクトリ（フォルダ）、l はショートカット（シンボリックリンク）
2〜4文字目 rw- 所有者の権限。読み(r)・書き(w)・実行(x)
5〜7文字目 r-- 所属グループの権限
8〜10文字目 r-- その他全員の権限

上の例なら、flows.json は「所有者 pi は読み書きでき、他の人は読むだけ」という状態です。Node-RED でファイル書き込みが失敗する場合は、この権限と、Node-RED を実行しているユーザーが誰なのかを確認することになります。

困ったら sudo を付ける、という癖はつけないでください

権限エラーを sudo で押し切ると、作られたファイルの所有者が root になり、次から一般ユーザーで扱えなくなることがあります。Node-RED 関連では sudo npm install がこの罠の代表格です。追加ノードの導入は、エディタの「パレットの管理」画面か、sudo を付けない npm install で行ってください。

7. プロセスとサービス：Node-RED が動き続ける仕組み

プロセスは「実行中のプログラム」

ディスク上のプログラムを起動すると、メモリ上に実体が作られます。これがプロセスで、それぞれに PID（プロセス ID）という番号が付きます。同じプログラムを2回起動すれば、プロセスは2つになります。Node-RED が二重に起動して「ポートが使用中（EADDRINUSE）」というエラーになるのは、この状態です。

サービス（デーモン）は裏で常駐するプロセス

画面を持たず、起動しっぱなしで仕事をするプロセスをサービス、あるいはデーモンと呼びます。Node-RED をラズパイで運用するときは、このサービスとして動かすのが基本形です。ターミナルを閉じても、ログアウトしても動き続けます。

systemd がサービスをまとめて管理する

サービスの起動・停止・自動起動・再起動を一手に引き受けているのが systemd（システムディー）です。Raspberry Pi OS でも Node-RED は systemd の管理下に置かれ、次のコマンドで操作します。

コマンド 意味
sudo systemctl start nodered 今すぐ起動する
sudo systemctl stop nodered 停止する
sudo systemctl restart nodered 再起動する（settings.js を変更したあとに使う）
sudo systemctl enable nodered 電源投入時に自動起動するようにする
sudo systemctl disable nodered 自動起動をやめる
systemctl status nodered 今動いているか、直近のログはどうかを確認する

start と enable は別物です

start は「今この場で起動する」、enable は「次回以降の電源投入時に自動で起動する」設定です。「電源を入れ直したら Node-RED が上がってこない」という相談の大半は、enable をしていないことが原因です。両方まとめてなら sudo systemctl enable --now nodered で済みます。

ラズパイの公式スクリプトで Node-RED を導入した場合は、node-red-start と node-red-stop という短いコマンドも用意されています。これらは内部で上記の systemctl を呼んでいるだけです。

8. 電源を入れてから使えるようになるまで

ラズパイの電源を入れてから Node-RED の画面を開けるようになるまでには、次の順で処理が進みます。トラブル時に「どこまで進んだか」を切り分けるための地図として使えます。

順 段階 内容
1 ブートローダー 本体のチップが SD カードの先頭（FAT32 の領域）を読み、起動用ファイルを探す
2 設定ファイルの読み込み config.txt と cmdline.txt を読み、ハードウェアの設定を決める
3 カーネルの起動 Linux カーネルがメモリに読み込まれ、CPU・メモリ・機器を初期化する
4 ルートファイルシステムの接続 SD カードの2つ目の領域（ext4）を / として接続し、全フォルダが見える状態にする
5 systemd の開始 最初のプロセス（PID 1）として起動し、以降のサービスを順に立ち上げる
6 各サービスの起動 ネットワーク、SSH、そして自動起動が有効なら Node-RED が起動する
7 ログイン待ち デスクトップ画面、またはログインプロンプトが表示される

Node-RED は 6 の段階で起動しますが、起動完了までには数十秒かかります。電源投入直後にブラウザで開こうとして繋がらない場合は、まだこの途中にいる可能性があります。

電源をいきなり抜かないでください

Linux は書き込み内容を一時的にメモリへ溜めてから SD カードに書きます。電源を直接切ると、この途中のデータが失われ、ファイルが壊れます。フローを保存した直後なら flows.json が壊れることもあります。終了は必ず sudo shutdown -h now（またはデスクトップのシャットダウン）で行い、緑の LED が点滅しなくなってから電源を抜いてください。

9. パッケージ管理：ソフトの入れ方が Windows と違う

Windows では、配布サイトから .exe をダウンロードして実行するのが普通です。Linux では、公式のソフト置き場（リポジトリ）から、コマンドで取り寄せて入れるのが基本です。この仕組みを担当するのが apt です。

sudo apt update # ソフト置き場の最新の一覧を取り直す sudo apt upgrade # 入っているソフトを最新版に更新する sudo apt install パッケージ名 # 新しく導入する

この方式には次の利点があります。

  • ダウンロード先を探す必要がなく、偽サイトを踏む危険がない
  • 必要な関連ソフト（依存関係）を自動でまとめて入れてくれる
  • 入っているソフト全部を apt upgrade の一発で更新できる

apt update は「更新」ではありません

名前から誤解されやすいのですが、apt update がするのはカタログの取り寄せだけで、ソフト自体は新しくなりません。実際に新しくするのは apt upgrade です。カタログが古いままだと最新版を見つけられないため、sudo apt update && sudo apt upgrade と続けて実行するのが慣例になっています。

apt と npm は別の世界

Node-RED を使っていると npm というもう一つのインストール手段も出てきます。両者は管理する対象が違います。

道具 管理するもの Node-RED での使いどころ
apt OS 全体のソフト（Node.js 本体、Python、Git など） 導入時と、OS の更新時
npm Node.js のライブラリ（追加ノード） 追加ノードの導入。通常はエディタの「パレットの管理」画面から行うため、直接打つ機会は少ない

10. Windows との対応表

Windows での経験を Linux に読み替えるための対応表です。完全に同じものではありませんが、最初のとっかかりとしては十分機能します。

Windows Linux / Raspberry Pi OS 補足
エクスプローラー ls、cd（ファイルマネージャもある） ヘッドレス運用ではコマンドが中心になる
コマンドプロンプト / PowerShell ターミナル + bash コマンド名はほぼ別物
C:\、D:\ のドライブレター / から始まる単一のツリー USB メモリなどはツリーの一部として接続（マウント）される
C:\Users\名前 /home/名前（略記は ~） 自分のデータはここに置く
Program Files /usr/bin、/usr/lib など 役割ごとに置き場所が分かれる
レジストリ /etc 以下のテキストファイル 設定は普通のテキストなので、エディタで読み書きできる
管理者として実行 sudo を頭に付ける コマンド1回だけ管理者になる
タスクマネージャー top、ps プロセスと負荷の確認
サービス（services.msc） systemctl Node-RED の自動起動もこれで設定する
イベントビューアー journalctl ログの確認
インストーラ（.exe） apt install 公式の置き場から取り寄せる
拡張子でファイル種別を判断 中身と実行権限で判断 Linux では拡張子は人間向けの目印にすぎない

11. まとめ

このガイドの要点

  • OS は「ハードとアプリの仲介役」。Linux はカーネルが中核で、シェルや画面はその上に乗った別のソフト
  • Raspberry Pi OS は Debian ベース。コードネーム（trixie / bookworm）で情報を調べると当たりが早い
  • 機器も情報も「ファイル」として見える。ファイルの読み書きを覚えると応用が利く
  • 普段は一般ユーザー、必要なときだけ sudo。むやみな sudo は後の権限トラブルを生む
  • Node-RED は systemd のサービスとして常駐させる。start は今すぐ、enable は次回から
  • ソフトの導入は apt。apt update はカタログの取り寄せで、更新は apt upgrade
