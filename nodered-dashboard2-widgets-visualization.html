📈 1. データ可視化ウィジェット概要

🎨 日常のアナロジー：車のダッシュボード

車を運転するとき、ダッシュボードを見ると様々な情報が視覚的に表示されています：

  • スピードメーター（ゲージ） - 現在の速度を針や数値で表示
  • 燃料計（ゲージ） - 残量をバーやセグメントで表示
  • 走行距離計（テキスト） - 累計距離を数値で表示
  • 燃費グラフ（チャート） - 時系列での変化を折れ線で表示

Dashboard 2.0のデータ可視化ウィジェットも同様に、IoTセンサーやシステムの状態を直感的に把握できる形で表示します。

🔧 2. サンプルフロー

📌 複数のフローを読み込むとき: このサイトの Dashboard 2.0 のフロー（サンプルフローと演習の解答例）は、すべて同じダッシュボード設定ノード（ui-base）を共有しています。2つ目以降のフローを読み込むと、「読み込もうとしているノードのいくつかは、既にワークスペース内に存在しています。」という通知が出ます。「コピーを読み込み」を選んでください。共有している設定ノードは既にあるものが使われ、どのフローのページも1つのダッシュボードにまとまります。ページはダッシュボードの左のメニューから選べます。ダッシュボード全体の見た目（ヘッダーやメニューの表示）は、最初に読み込んだフローの ui-base の設定になります。

ページが表示されないとき: ダッシュボードの設定ノード（ui-base）が2つ以上あると、そのうち1つのページしか表示されません。このサイトの以前の版のフローを読み込んでいると、この状態になります。以前の版のフローのタブを削除してから、エディタの メニュー → 設定ノード を開き、画面上部の「未使用」を選んで、どのノードからも使われていない ui-group・ui-page・ui-base・ui-theme を削除します。ui-group を消すとそれを使っていた ui-page が、ui-page を消すと ui-base が未使用になるので、未使用のものが無くなるまで繰り返してください。そのあとで、フローを読み込み直します。

📥 サンプルフローを試す手順:

  1. 下のフローJSONを「コピー」ボタンでコピー
  2. Node-REDエディタで メニュー → 読み込み を選択
  3. JSONをペーストして「読み込み」をクリック
  4. エディタ右上の「デプロイ」ボタンをクリック（クリックするまでフローは動きません）
  5. ブラウザでダッシュボード（http://localhost:1880/dashboard）を開き、左のメニューからページを選んで動作を確認

公式サンプルフロー

最初のサンプルフローは、Dashboard 2.0 の開発元である FlowFuse が公開している公式サンプルを、1つのタブにまとめたものです。出典は次の2か所です。

  • 公式ドキュメント: 各ウィジェットの解説ページ（dashboard.flowfuse.com）に載っているサンプル。表の1列目に、載っているページを書いています
  • GitHub examples: GitHub リポジトリの examples フォルダにあるサンプル。npm パッケージには含まれないため、Node-RED エディタの メニュー → 読み込み → サンプル には出てきません

ノードの設定値とノードIDは公式のままです。このサイトで手を加えたのは次の点だけです。

  • 1つのタブにまとめ、例が重ならないよう位置をずらし、例の名前を書いたコメントノードを置いた
  • GitHub examples はグループ（ui-group）が空のままで、読み込んでもダッシュボードに表示されない。そこで「GitHub Examples（可視化系）」ページ（/flowfuse-examples-visualization）と例ごとのグループを用意し、各ウィジェットに割り当てた
  • 同じ設定ノード（ui-base など）が例ごとに少しずつ違う値で入っていたため、1つにそろえた
例（出典・表示されるページ） 内容
chart-line-multiple
公式ドキュメント（ui-chart）
/dashboard/charts		 「Sample Data A」「Sample Data B」の Inject が、propertyA と propertyB を持つオブジェクトの配列を送ります。chart は propertyA を x 軸、propertyB を y 軸にとり、msg.topic ごとに別の線で描きます。「Clear Chart」は空の配列を送って、グラフを消します。
chart-bar-finance-grouped
公式ドキュメント（ui-chart）
/dashboard/charts		 年ごとの四半期の値（{"year":2021,"Q1":115,...}）を送り、年を x 軸にして、Q1〜Q4 の棒を並べます。系列（Q1〜Q4）は chart の設定に JSON で書いてあり、1つのオブジェクトの複数のキーを、それぞれ別の棒にする例です。
chart-pie-doughnut
公式ドキュメント（ui-chart）
/dashboard/charts		 年・四半期・収益のデータを、ドーナツグラフと円グラフで表示します。どちらも年ごとに輪を分け、四半期を区分、収益を大きさにしています。ドーナツ側の「Finance Data」は2021年と2022年の8件を送るので輪が2つ、円グラフ側は2021年の4件だけなので輪が1つになります。名前の無い Inject は空の配列を送って、グラフを消します。
chart-scatter-grouped
公式ドキュメント（ui-chart）
/dashboard/charts		 series・x・y を持つ点の配列を送り、series（A・B・C）ごとに色を分けた散布図を描きます。
ui-table-cell-types
公式ドキュメント（ui-table）
/dashboard/table		 デプロイすると Inject が自動で1回動き、表に2行のデータを送ります（Inject のボタンで送り直せます）。列ごとに表示形式（リンク、プログレスバー、折れ線・棒の小さなグラフ、チェック／バツ、色の点、日時など）を変えた例です。
guage
GitHub examples
/dashboard/flowfuse-examples-visualization		 Inject のボタンを押すと、数値 72 をゲージに送ります。ゲージは 0〜100（単位 °F）の針の形で、値の範囲ごとに色を変えています。例の名前の綴り（guage）は公式のファイル名のままです。

progress の公式サンプルはありません。progress は、次の応用フローで扱います。

📈 3. chart（チャート）

表示 chart ウィジェット

時系列データや比較データを視覚的に表示するチャートウィジェットです。eChartsライブラリをベースに、折れ線グラフ、棒グラフ、散布図、円グラフ、ヒストグラムなど多彩な表現が可能です。

🔹 対応チャートタイプ

📈

Line（折れ線）

時系列データの推移表示に最適

📊

Bar（棒グラフ）

カテゴリ別の比較に最適

⚬

Scatter（散布図）

2変数の相関分析に最適

🥧

Pie/Doughnut（円）

構成比の表示に最適

📶

Histogram

度数分布の表示に最適

🔹 主要プロパティ

chart はエディターが部分的に日本語化されている（ui_chart の ja ロケールあり）。ja 翻訳のあるキーは日本語表示、無いキー（Area／Pie／Doughnut／Histogram、Interpolation、Stack Series、X／Y Format・Label、Text／Grid Color 等）は英語表示なので「英語ラベル（日本語訳）」で示す。エディターのセクション（先頭／Chart Configuration／Axis Configuration／Styling・Colors）ごとに分けて解説する。グラフの種類によって表示される項目は変わる。

🔹 補間方法（Interpolation）

折れ線グラフでポイント間をどう描画するかを選択できます：

⚠️ ui-chart には以下の既知の不具合・注意点が報告されています（Dashboard 2.0、eCharts ベース）。

長時間稼働や複雑な構成で利用する場合は、特に下表のワークアラウンドを設計に取り入れてください。

確認時点: 2026-09-12、@flowfuse/node-red-dashboard 1.31.0 のソースで確認しました。「Dashboard 2.0」は製品名で、パッケージのバージョンは 1.x です（2.x というバージョンは存在しません）。

バージョンによる違い: ui-chart の描画エンジンは 1.27.0（2025-09-10）で Chart.js から eCharts へ変わりました。1.26.x 以前を使っている場合、下表のうち eCharts 固有の記述（formatter など）は当てはまりません。

分類 現象 影響 暫定対策
複数系列 複数 series を含むリアルタイム payload を順次送ると、ブラウザ更新やページ切替後にチャート内容が消える。 監視画面・時系列表示で、リロード後に履歴表示が空になる。 更新・ページ切替後に過去データを再送する設計、または一時的に series ごとにメッセージを分割。
動的オプション 毎サンプルごとに msg.ui_update.chartOptions を送ると、そのたびに全オプションの再マージと setOption() の再適用が走る。 送信頻度に比例して CPU 使用率が増え、画面が遅延する。 chartOptions は毎回送らず、初期化時・変更時のみ送る。必要に応じて throttle / rate limit を入れる。
series オプション msg.ui_update.chartOptions.series の設定がページ更新で永続しない。データ到着前や非表示ページのチャートに送ると反映されないことがある。 線色・系列別設定が意図どおり残らない。 データ投入後に series オプションを再送する。series には name と type を必ず明示する。
legend 必要な series / value キーを持たないデータが混じると、凡例に undefined が表示される。 凡例が汚れる。不要データが内部で保持・再送される可能性。 chart ノードへ送る前に switch ノードで、必要なキーを持つデータだけを通す（条件「キーを含む」で series や value を指定）。
X 軸 棒グラフなどで重複する X ラベルを使うと、後続データが前のデータを上書きするように見える。 「今日 00–23時」「明日 00–23時」のような重複ラベル表示で不都合。 内部 X 値は一意にし、表示ラベルだけ短縮する。eCharts の formatter を活用。
極端な数値 Number.MAX_VALUE や極端値を含むと Y 軸の自動スケールで描画不能となり、タブクラッシュに至るケースもある。 センサー異常値や桁あふれで画面が壊れる可能性。 chart 投入前に値を検証し、上限・下限でクリップ。異常値は別表示にする。
大量 series 非表示の系列が多数あっても更新処理が走り、描画・操作が重くなる。 多数系列の監視画面でブラウザが固まる。 非表示系列は chart data から外す、表示系列数を制限、サーバ側で間引きを行う。
💡 設計時のチェックリスト:
  • msg.ui_update.chartOptions は変更時だけ送る（毎サンプル送らない）
  • chart ノード前で 必ず 入力データを検証し、series / x / y が欠けたデータを除外する
  • 長期稼働の監視画面では、ブラウザ更新・ページ切替・再接続時の再描画テストを必ず実施する
  • X 軸ラベルは内部値を一意にし、表示用フォーマットを別途指定する

💊 まず試したい応急処置：「Clear Chart History」ボタン

上記のような不具合（凡例に undefined が残る、過去データが壊れている、 複数系列の表示が崩れているなど）が発生した場合、 chart ノードの編集ダイアログ左上にある「Clear Chart History」ボタン を押すと、内部に蓄積された履歴データがクリアされて表示が正常に戻るケースがあります。 根本解決ではありませんが、配信中のダッシュボードを止めずに復旧したい場合に有効です。

▲ chart ノードの編集ダイアログ。左上の「Clear Chart History」ボタンで履歴をクリアできる。

💡 「Clear Chart History」の使いどころ:

✅ 8. まとめ

📊 データ可視化ウィジェットの使い分け

ウィジェット 最適な用途 入力データ形式
chart (Line) 時系列データの推移、トレンド分析 数値 + topic
chart (Bar) カテゴリ別比較、期間別集計 配列 / オブジェクト
chart (Pie) 構成比、割合の表示 配列 / オブジェクト
gauge (3/4, Half) 現在値の直感的表示、しきい値監視 数値
gauge (Tile) コンパクトな数値表示 数値
gauge (Battery, Tank) 残量、レベル表示 数値（%）
table 一覧表示、詳細データ確認 オブジェクト配列
progress 進捗状況、完了率 数値（%）

💡 重要ポイント

  • 時系列チャート: X-Axis Limitを設定して表示期間を制限（メモリ節約）
  • 複数系列: msg.topicでデータをグループ化
  • ゲージのセグメント: 閾値に応じた色分けで異常を視覚化
  • 動的プロパティ: msg.ui_updateで実行時に設定変更可能
  • チャートクリア: 空配列 [] を送信してリセット

問題 原因 解決方法
チャートにデータが表示されない Y軸のプロパティ指定ミス データ構造を確認し、正しいキーを指定

🏭 10. 実務活用例

ケース1: 工場環境モニタリング

温度・湿度・気圧センサー → chart（時系列推移） → gauge（現在値表示） → 閾値超過時にnotification

ケース2: 生産ライン稼働状況

各設備の稼働率データ → chart（棒グラフで比較） → progress（全体稼働率） → table（設備別詳細）

ケース3: エネルギー管理ダッシュボード

電力・ガス・水道使用量 → chart（時間帯別消費量） → gauge（リアルタイム消費） → chart（円グラフで構成比）

ケース4: IoTセンサーネットワーク

複数センサーからのMQTTデータ → table（センサー一覧・状態） → chart（選択センサーの履歴） → gauge（バッテリー残量）
