1. 概要

Node-RED には2種類のファイル操作ノードがあります：

Write File（書き込み）

Write File

役割: ファイルへの書き込みや追記、削除

用途:

  • ログファイルの作成
  • データの永続化
  • 設定ファイルの保存

Read File（読み込み）

Read File

役割: ファイルからの読み込み

用途:

  • 設定ファイルの読み込み
  • データファイルの処理
  • テンプレートの読み込み

ファイルキャビネットに例えると：Write File ノードは書類をキャビネットに入れる作業、Read File ノードはキャビネットから書類を取り出す作業です。

動作を図で見る

write file ノードは msg.payload をファイルに書き込み、read file ノードはファイルの中身を読み出して msg.payload に入れます。

2. Write File（書き込み）ノード

プロパティ

設定項目説明既定値
ファイル名書き込み先のファイルパス。入力欄左の型選択で パス／msg／JSONata／env を切り替えられる（空）
動作ファイルに対する操作。下の「動作の種類」から選ぶ。「ファイルを削除」を選ぶと、下の3項目（改行・ディレクトリ・文字コード）は表示されなくなるファイルへ追記
メッセージの入力のたびに改行を追加メッセージごとに末尾へ改行を付けるか（チェックボックス）。動作が「ファイルを削除」のときは表示されないオン
ディレクトリが存在しない場合は作成書き込み先の親ディレクトリがなければ自動で作成するか（チェックボックス）。動作が「ファイルを削除」のときは表示されないオフ
文字コード書き込み時の文字エンコーディング。動作が「ファイルを削除」のときは表示されないデフォルト
名前エディター上のノード表示名（空）

「動作」の種類

選択肢説明用途
ファイルへ追記既存の内容を残し、ファイル末尾に書き足すログファイル、時系列データ
ファイルを上書き既存の内容を消してから書き込む設定ファイル、状態保存
ファイルを削除指定したファイルを削除する一時ファイルの削除

動的なファイル名

「ファイル名」の左側の種類を msg. にし、右側に filename と入力すると（msg.filename と表示されます）、メッセージごとに msg.filename でファイルパスを指定できます。ファイル名を空欄のままにすると、エラー（Invalid property expression: zero-length）になって書き込めません。

// Function ノードで動的にファイル名を設定 msg.filename = "/home/pi/logs/sensor_" + new Date().toISOString().slice(0,10) + ".log"; msg.payload = "センサーデータ: " + msg.payload; return msg;

3. Read File（読み込み）ノード

プロパティ

設定項目説明既定値
ファイル名読み込むファイルパス。入力欄左の型選択で パス／msg／JSONata／env を切り替えられる（空）
出力形式ファイル内容をどの形で出力するか。下の「出力形式の種類」から選ぶ文字列
各メッセージに既存の全プロパティを含める出力形式が「行毎のメッセージ」「バッファのストリーム」のとき表示。分割した各メッセージに、入力メッセージの他のプロパティも引き継ぐか（チェックボックス）オフ
文字コード読み込み時の文字エンコーディング（出力形式が「文字列」「行毎のメッセージ」のときだけ表示される）デフォルト
名前エディター上のノード表示名（空）

「出力形式」の種類

選択肢説明用途
文字列ファイル全体を1つの文字列で出力する設定ファイル、テンプレート
行毎のメッセージ1行ごとに分割し、複数のメッセージで出力するCSVの行処理、ログ解析
バイナリバッファファイル全体を Buffer オブジェクトで出力するバイナリファイル、画像
バッファのストリームバッファのストリームとして出力する大きなファイルの処理

ポイント:

  • msg.filename で動的にファイルを指定可能
  • 大きなファイルは「行毎のメッセージ」または「バッファのストリーム」を使用
  • 読み込み完了時に msg を出力

使用パターン

パターン1: ファイルへの書き込み（追記）

サンプルフローの「ファイルへの書き込み（追記）」を参照してください。

メッセージ → 追記 → 完了

用途: タイムスタンプを付けたデータをログファイルへ追記

設定: 動作: ファイルへ追記、メッセージの入力のたびに改行を追加: ✓

パターン2: ファイルの読み込み

サンプルフローの「ファイルの読み込み」を参照してください。

読み込み → Read File → 内容表示

用途: 保存済みログファイルの内容をまとめて読み込み

設定: 出力形式: 文字列

パターン3: 上書き保存

サンプルフローの「上書き保存」を参照してください。

新データ → 上書き → 保存完了

用途: 設定用オブジェクトをJSONファイルとして上書き保存

設定: 動作: ファイルを上書き（既存ファイルを置き換え）

パターン4: 動的ファイル名（日付別ログ）

サンプルフローの「動的ファイル名（日付別ログ）」を参照してください。

データ → 日付でファイル名生成 → 動的ファイル

用途: 日付ごとに切り替わるファイルへのイベント記録

設定: ファイル名: msg.filename

パターン5: エラーハンドリング

サンプルフローの「エラーハンドリング」を参照してください。

読み込み試行 → 成功時 ｜ Catch → エラー時

用途: 存在しないファイルへのアクセスで発生するエラーの捕捉

ポイント: Catch ノードでファイルエラー（存在しない、権限なし等）をキャッチ

5. 演習問題

演習1: 基本的なログ出力 初級

課題: Inject ノードのボタンを押すたびに、タイムスタンプ付きのメッセージをログファイルに追記してください。

💼 使いどころ: 何らかのイベントが起きるたびに、発生時刻を添えてログファイルへ追記する場面で使います。

成功の条件:

  • Inject ボタンを押すたびに /tmp/exercise1.log にタイムスタンプ付きの行が追記される
  • cat /tmp/exercise1.log を実行すると複数行のログが確認できる
  • デバッグパネルにノードのステータスとして「追記完了」が表示される
💡 ヒント

タイムスタンプを付ける: Change ノードの「値の代入」で msg.timestamp に「日時」型の YYYY-MM-DDTHH:mm:ss.sssZ（ISO 8601形式）を設定し、Template ノードで {{{timestamp}}} - {{{payload}}} のように1行の文字列を組み立てます。{{{ }}}（波かっこ3つ）は、値を HTML 用に書き換えずにそのまま入れる書き方です。

ファイルへの書き込み: file ノードの「動作」を「ファイルへ追記」に設定し、「メッセージの入力のたびに改行を追加」をオンにします。

💼 使いどころ: 保存済みのログファイルの中身をまとめて取り出し、内容を確認する場面で使います。

  • デバッグパネルに文字列としてログの全行が表示される
  • ファイルが存在しない場合はエラーメッセージがデバッグパネルに表示される

演習3: JSON設定ファイルの保存と読み込み 中級

課題: 設定オブジェクトをJSONファイルとして保存し、別のフローで読み込んでオブジェクトとして使用してください。

💼 使いどころ: アプリの設定内容をファイルに保存しておき、必要なときに読み込んで使う場面で使います。

成功の条件:

  • 「設定保存」ボタンを押すと /tmp/config.json が作成され、中身が有効なJSON形式である
  • 「設定読込」ボタンを押すとデバッグパネルにJavaScriptオブジェクトとして設定が表示される
  • ノードステータスに server プロパティの値（例: "localhost"）が表示される
💡 ヒント

保存時: 設定オブジェクトは Inject ノードの msg.payload に「JSON」型で書きます。JSON ノードの「動作」を「常にJSON文字列に変換」にして文字列にし、file ノードで書き込みます。「JSON文字列フォーマット」をオンにすると、改行と字下げの入った読みやすい形で保存されます。file ノードはオブジェクトを受け取ると自動で JSON 文字列にしますが、その場合は1行に詰めて書かれます。

読み込み時: file in ノードで文字列として読み込み、JSON ノードでオブジェクトに戻します。

演習4: 日付別ローテーションログ 上級

課題: センサーデータを日付別のファイルに保存し、7日以上前のファイルを自動削除する仕組みを作成してください。

💼 使いどころ: センサーデータを日付ごとのファイルに分けて記録し、古い日付のファイルを整理する場面で使います。

成功の条件:

  • 「センサーデータ」ボタンを押すと /tmp/sensor_YYYY-MM-DD.log 形式のファイルにデータが追記される
  • ノードステータスに現在の保存先ファイルパスが表示される
  • 「古いファイル削除」ボタンを押すと7日前の日付のファイルが削除（または削除試行）される
  • 毎回ボタンを押すたびにタイムスタンプ付きのデータが同じ日付ファイルに蓄積される
💡 ヒント

ファイル名の指定: file ノードの「ファイル名」を msg.filename にすると、メッセージごとにファイル名を変えられます。削除は「動作」で「ファイルを削除」を使用します。

日付入りのファイル名を作る: Change ノードの「値の代入」で、msg.filename に「JSONata式」型の式を設定します。

  • 今日: "/tmp/sensor_" & $substring($now(), 0, 10) & ".log"。$now() は現在時刻を 2026-10-02T03:04:05.678Z の形で返し、$substring(…, 0, 10) で先頭10文字（日付の部分）を取り出します。& は文字列をつなぐ演算子です
  • 7日前: $now() の代わりに $fromMillis($millis() - 7 * 24 * 60 * 60 * 1000) を使います。$millis() は現在時刻のミリ秒で、そこから7日分のミリ秒を引いて日時に戻しています

書き込む行は、同じ Change ノードの2つ目のルールで msg.payload に「JSONata式」型の $now() & "," & payload を設定して作ります（例: 2026-10-02T03:04:05.678Z,25.5）。

日付は UTC（協定世界時）で決まります。日本時間の午前0時〜9時の間は、前日の日付のファイルになります。

6. まとめ

重要ポイント:

  • Write File: 書き込みや追記、削除（append / overwrite / delete）
  • Read File: 読み込み（文字列 / Buffer / 行ごと / ストリーム）
  • msg.filename で動的にファイルパスを指定可能
  • 「Create directory」で親ディレクトリを自動作成

注意事項:

  • ファイルパスの権限に注意（読み書き権限が必要）
  • 大きなファイルは「行毎のメッセージ」または「バッファのストリーム」を使用
  • 重要なファイル操作には Catch ノードでエラーハンドリング
  • 相対パスはNode-REDの作業ディレクトリ基準

別のマシンとファイルをやり取りするには:

fileノードが扱うのは、Node-RED が動いているマシンの中のファイルです。計測器やカメラなど別のマシンとファイルを受け渡す場合は、FTP / SFTP ノードガイドを参照してください。転送で取得したファイルの中身を使うには、そのあとに Read File を繋ぐ必要があります。
