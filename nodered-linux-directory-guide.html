1. ドライブレターがない世界

Windows では、SSD が C:、USB メモリが D: というように、装置ごとに独立したツリーがあります。Linux にはこの区別がありません。すべてが /（ルート）を頂点とする1本のツリーに収まります。

では USB メモリはどう扱われるのか。ツリーのどこかのフォルダに「接続」して、その中身として見せます。この接続をマウントと呼びます。デスクトップ版の Raspberry Pi OS に USB メモリを挿すと、自動的に /media/ユーザー名/ラベル名 にマウントされ、そのフォルダを開けば中のファイルが見えます。

Windows Linux
C:\Users\taro\data.csv /home/taro/data.csv
D:\log\sensor.txt（USB メモリ） /media/taro/USB16GB/log/sensor.txt
区切りは \（円記号・バックスラッシュ） 区切りは /（スラッシュ）

大文字と小文字は区別されます

Windows では Data.csv と data.csv は同じファイルですが、Linux では別のファイルです。Node-RED の File ノードでパスを指定してもファイルが見つからないとき、この打ち間違いが原因のことがよくあります。

2. パスの読み方・書き方

パスとは、ファイルやフォルダの住所です。書き方は2種類あります。

種類 例 意味
絶対パス /home/taro/.node-red/flows.json / から始まる完全な住所。どこから実行しても同じ場所を指す
相対パス .node-red/flows.json 今いる場所を起点にした住所。今いる場所が変われば、指す先も変わる

パスの中で使える特別な記号は次の4つです。

記号 意味 使用例
/ ルート（最上位）、または区切り文字 cd / でルートへ移動
~ 自分のホームディレクトリ（/home/ユーザー名） cd ~/.node-red
. 今いるディレクトリ ./script.sh で今いる場所のスクリプトを実行
.. 1つ上のディレクトリ cd .. で親へ戻る

先頭が . のファイルは「隠しファイル」です

.node-red、.bashrc のように名前がドットで始まるものは、通常の ls では表示されません。見るには ls -a を使います。設定ファイルの多くはこの形なので、「フォルダが見当たらない」ときはまず ls -a を試してください。Node-RED の作業フォルダ ~/.node-red も隠しフォルダです。

スペースを含むパスは要注意

/home/taro/my data/log.csv のようにスペースがあると、コマンドはそこを区切りだと解釈します。引用符で囲むか（"my data"）、そもそもファイル名やフォルダ名にスペースと日本語を使わないのが安全です。Node-RED のファイルパス指定でも同じ注意が要ります。

3. ルート直下の全体像

ls / で見えるフォルダを、役割ごとに整理したものが次の図です。オレンジ色は Node-RED の運用でよく触る場所です。

/ ← すべての出発点（ルート） ├── bin sbin lib ← 基本コマンドと部品（実体は usr の中） ├── usr/ ← インストールされたソフト本体 │ ├── bin/ ← 一般ユーザー向けコマンド（node, git, python3） │ ├── sbin/ ← 管理者向けコマンド │ ├── lib/ ← ライブラリ、systemd のサービス定義 │ ├── share/ ← アイコン・説明書などのデータ │ └── local/ ← 自分で入れたソフト（apt 以外） ├── etc/ ← システム全体の設定ファイル置き場 ├── var/ ← 動くほどに増減するデータ（ログ、キャッシュ） │ ├── log/ ← ログファイル │ └── tmp/ ← 再起動しても消えない一時ファイル ├── home/ ← 各利用者の作業場所 │ └── taro/ ← ~ が指す場所 │ └── .node-red/ ← Node-RED のフロー・設定・追加ノード ├── root/ ← root 専用のホーム（/ とは別物） ├── boot/ ← 起動に必要なファイル │ └── firmware/ ← config.txt などの設定（bookworm 以降） ├── dev/ ← 装置がファイルとして並ぶ（USB、GPIO、SD） ├── proc/ sys/ ← カーネルの内部情報。実体のない仮想フォルダ ├── tmp/ ← 一時ファイル。再起動で消える ├── mnt/ media/ ← 外付け装置の接続先（USB メモリなど） ├── opt/ ← 大きな追加ソフトの置き場 └── srv/ ← サーバー用の公開データ（あまり使わない）

/bin と /usr/bin が両方あるのはなぜか

歴史的な事情で分かれていましたが、現在の Debian／Raspberry Pi OS では /bin は /usr/bin へのショートカット（シンボリックリンク）になっており、中身は同じです。/lib と /usr/lib、/sbin と /usr/sbin も同様です。どちらのパスで書かれた記事も同じ場所を指していると考えて構いません。

4. 主要ディレクトリの役割

名前の由来を添えた一覧です。由来を知っておくと記憶に残りやすくなります。

ディレクトリ 名前の由来 役割と、そこで出会うもの
/bin
/usr/bin		 binary（実行ファイル） コマンドの実体。ls、cat、node、git などがファイルとして置かれている
/sbin
/usr/sbin		 system binary 管理者向けコマンド。reboot、shutdown、fdisk など
/etc etcetera（諸々） システム全体の設定ファイル。すべてテキストなので読める。/etc/hostname（機器名）、/etc/fstab（起動時のマウント設定）など
/var variable（変動する） 使ううちに増減するデータ。ログ（/var/log）、キャッシュ、データベースの実体
/home home 利用者ごとの作業場所。ユーザー taro なら /home/taro。自分のファイルはここに置く
/root root 管理者 root 専用のホーム。/（ルート）とは別のフォルダなので混同しないこと
/usr Unix System Resources OS 標準やインストール済みソフトの本体。/usr/local は apt を通さずに自分で入れたソフト用
/tmp temporary 一時ファイル。再起動すると消えるため、残したいデータを置いてはいけない
/dev device（装置） 装置がファイルの形で並ぶ。/dev/ttyUSB0（USB シリアル）、/dev/gpiochip0（GPIO）、/dev/mmcblk0（SD カード）
/proc process 実行中プロセスとカーネルの情報。ディスク上に実体はなく、読むたびに生成される。/proc/cpuinfo、/proc/meminfo
/sys system ハードウェアの状態と設定。CPU 温度（/sys/class/thermal/...）や LED の制御もここ
/boot boot（起動） 起動に必要なカーネル本体と設定。ラズパイでは /boot/firmware が実質の設定置き場
/media media USB メモリなどの自動マウント先。/media/ユーザー名/ラベル
/mnt mount 手動でマウントするときの場所。ネットワーク共有などをここに繋ぐ
/opt optional 配布元がひとまとまりで提供する大きなソフトの置き場
/lib
/usr/lib		 library 共通部品。systemd のサービス定義（nodered.service など）もここ

5. 覚え方は3原則で足りる

20個すべてを覚える必要はありません。日常的に必要なのは次の3つです。

  1. 設定は /etc：システムの設定を変えたいときに探す場所
  2. ログや増えるデータは /var：状況を調べたいときに見る場所
  3. 自分のものは /home（~）：自分で作る・置く・バックアップする場所

これにラズパイ特有の /boot/firmware（ハードウェア設定）と /dev（装置）を足せば、実務で困る場面はほぼ網羅できます。

6. Raspberry Pi 固有のディレクトリ

/boot/firmware：ハードウェアの設定置き場

SD カードには2つの領域があり、1つ目は Windows でも読める FAT32 形式です。ここに起動用のファイルが入っており、Linux 側からは /boot/firmware として見えます。

ファイル 役割
config.txt ハードウェアの設定。I2C や SPI の有効化、画面解像度、オーバークロックなど。raspi-config で設定を変えると、実際にはこのファイルが書き換わる
cmdline.txt カーネルに渡す起動オプション。1行で書く決まりがあり、改行を入れると起動しなくなる
*.dtb、overlays/ 接続する機器の構成情報。センサー基板の有効化などで使う

OS のバージョンで場所が違います

bookworm 以降は /boot/firmware/config.txt、bullseye 以前は /boot/config.txt です。ネット上の古い記事のとおりに /boot/config.txt を編集しても効かない場合は、この違いが原因です。自分の環境は ls /boot/firmware/ を実行し、中身が表示されるかどうかで判別できます。

SD カードを PC に挿すと、この領域だけが見えます

FAT32 の領域は Windows からも読み書きできます。そのため、ラズパイが起動しなくなったときでも、PC に SD カードを挿して config.txt を直せば復旧できることがあります。ヘッドレス設定で ssh という空ファイルをここに置く手法も、この仕組みを使っています。

/dev：ラズパイでよく使う装置ファイル

パス 内容
/dev/ttyUSB0、/dev/ttyACM0 USB 接続のシリアル機器（USB-RS485 変換器、Arduino など）。MODBUS RTU の設定で指定する
/dev/serial0 本体の GPIO ピンにあるシリアルポートへの別名
/dev/i2c-1 I2C バス。センサー基板の接続に使う（raspi-config での有効化が必要）
/dev/gpiochip0 GPIO ピン群
/dev/mmcblk0 SD カード本体。p1、p2 が各領域
/dev/sda1 USB 接続のストレージ（USB メモリ、SSD）

USB シリアル機器を挿したあとに ls /dev/tty* を実行し、増えたものが今挿した機器です。この確認は MODBUS やシリアル通信の設定で頻繁に使います。

7. Node-RED ファイルの居場所マップ

Node-RED 関連のファイルがどこにあるかをまとめます。ユーザー名が taro の場合の例です。

/home/taro/.node-red/ ← ユーザーディレクトリ。フローの本拠地 ├── flows.json ← フローの実体。バックアップの最重要ファイル ├── flows_cred.json ← パスワード等の認証情報（暗号化されている） ├── settings.js ← 設定ファイル。ポート番号、認証、テーマなど ├── package.json ← 導入済み追加ノードの一覧 ├── node_modules/ ← 追加ノードの実体（サイズが大きい） ├── lib/ ← エディタから保存したフローや関数の断片 └── projects/ ← プロジェクト機能を使う場合の Git リポジトリ /usr/lib/systemd/system/ └── nodered.service ← 自動起動の定義（/lib/systemd/system/ でも同じ場所） /usr/bin/ ├── node ← Node.js 本体 ├── node-red ← Node-RED 起動コマンド ├── node-red-start ← サービスとして起動（公式スクリプト導入時） ├── node-red-stop ← サービス停止 └── node-red-log ← ログ表示
やりたいこと 見る場所・打つコマンド
フローをバックアップしたい ~/.node-red/ の flows.json、flows_cred.json、settings.js、package.json をコピーする。node_modules は npm install で復元できるので不要
ポート番号や認証を変えたい ~/.node-red/settings.js を編集し、sudo systemctl restart nodered
ログを見たい node-red-log、または journalctl -u nodered -f
自動起動の設定を確認したい systemctl is-enabled nodered
導入済みノードを確認したい cat ~/.node-red/package.json

flows_cred.json は単体では復元できません

認証情報は settings.js の credentialSecret（または自動生成された鍵）で暗号化されています。バックアップから戻すときは settings.js と対で扱う必要があります。片方だけ戻すと、MQTT やデータベースのパスワードが復号できません。

ユーザーディレクトリの場所は変更できます

標準は ~/.node-red ですが、起動時に node-red -u /path/to/dir と指定すれば別の場所を使えます。実際にどこが使われているかは、起動ログの冒頭に User directory : /home/taro/.node-red として表示されます。

8. 自分のファイルはどこに置くべきか

センサーのログ、自作スクリプト、CSV の出力先——これらをどこに置くかは、次の基準で決めます。

置くもの 推奨する場所 理由
Node-RED が書き出すログ・CSV /home/taro/data/ 権限の問題が起きず、バックアップもホームごとで済む
自作のシェルスクリプト /home/taro/bin/ Exec ノードから絶対パスで呼べる。システム領域を汚さない
一時的な作業ファイル /tmp/ 再起動で自動的に消えるので、掃除の手間が不要
大量に書き込むログ USB メモリや SSD（/media/...） SD カードは書き込み回数に寿命がある。長期運用では外部ストレージが安全

SD カードへの大量書き込みは寿命を縮めます

1秒ごとにセンサー値を追記するようなフローを SD カードだけで長期間動かすと、数か月でカードが壊れることがあります。書き込み間隔を長くする、まとめて書く（Batch ノード）、外部ストレージやデータベースに送る、といった対策を検討してください。

9. 場所を調べるコマンド

地図を覚えるより、探せるほうが実用的です。次の6つを押さえておけば足ります。

コマンド 用途
pwd 今いる場所を絶対パスで表示する
ls -la 隠しファイルも含め、権限・所有者・サイズ付きで一覧する
which node コマンドの実体がどこにあるかを表示する
find ~ -name "flows.json" ホーム以下から名前でファイルを探す
du -sh ~/.node-red そのフォルダが使っている容量を表示する
df -h SD カードの空き容量を確認する
cd ~/.node-red pwd /home/taro/.node-red ls -la -rw-r--r-- 1 taro taro 4521 Aug 5 09:12 flows.json -rw-r--r-- 1 taro taro 120 Aug 5 09:12 flows_cred.json -rw-r--r-- 1 taro taro 20481 Jul 30 14:02 settings.js df -h / Filesystem Size Used Avail Use% Mounted on /dev/mmcblk0p2 29G 6.2G 22G 23% /

ディスクが満杯だと Node-RED は保存に失敗します

df -h の Use% が 100% になっていると、フローの保存もログの記録もできません。原因の多くはログの肥大化です。容量を食っている場所は sudo du -sh /var/log/* で特定できます。

10. 触らない場所・バックアップする場所

むやみに触らない場所

場所 理由
/usr、/bin、/lib OS 本体。ファイルを消すとコマンドが動かなくなる。変更は apt に任せる
/proc、/sys カーネルの内部。書き込みが直接ハードウェアの動作を変える。意味を理解せずに書かない
/boot/firmware/cmdline.txt 1行の書式が崩れると起動しなくなる。編集前に必ずコピーを取る
/etc 全般 編集する前に sudo cp ファイル名 ファイル名.bak で控えを取る習慣をつける

バックアップすべき場所

ラズパイの故障や SD カードの寿命に備えて、最低限これだけは別の場所に保存しておきます。

# ホームに日付名のフォルダを作り、必要な4点をコピーする mkdir -p ~/backup-20260807 cp ~/.node-red/flows.json ~/backup-20260807/ cp ~/.node-red/flows_cred.json ~/backup-20260807/ cp ~/.node-red/settings.js ~/backup-20260807/ cp ~/.node-red/package.json ~/backup-20260807/

作成したフォルダは、USB メモリや PC などラズパイの外にコピーして初めてバックアップとして機能します。SD カードの中に置いたままでは、カードが壊れたときに一緒に失われます。

11. 演習

演習1（初級）

ユーザー名が taro のとき、次のパスはそれぞれ何を指しますか。

  1. ~/.node-red/settings.js
  2. /etc/hostname
  3. ../data/log.csv（今いる場所が /home/taro/work のとき）
解答を見る
  1. /home/taro/.node-red/settings.js。~ は自分のホームを指すので、絶対パスに直すとこうなる。Node-RED の設定ファイル
  2. この機器のホスト名が書かれた設定ファイル。/etc なのでシステム全体の設定
  3. /home/taro/data/log.csv。.. で /home/taro に上がってから data/log.csv へ降りる

演習2（初級）

次の目的に対して、どのディレクトリを見ればよいか答えてください。

  1. I2C を有効にする設定を書き換えたい（Raspberry Pi OS bookworm 以降）
  2. USB シリアル変換器が認識されているか確かめたい
  3. OS の起動時のエラーメッセージを探したい
解答を見る
  1. /boot/firmware/config.txt。ただし通常は直接編集せず、sudo raspi-config から設定するほうが安全
  2. /dev。ls /dev/ttyUSB* で確認する
  3. /var/log。ただし現在の Raspberry Pi OS ではジャーナル形式が中心なので、journalctl -b のほうが確実

演習3（中級）

Node-RED の File ノードで、センサーの値を毎時 CSV に追記したい。保存先のパスとして適切なものを選び、理由を説明してください。

  1. /tmp/sensor.csv
  2. /home/taro/data/sensor.csv
  3. /etc/sensor.csv
解答を見る

正解は 2 です。

  • 1（/tmp）：書き込みはできるが、再起動でファイルごと消える。蓄積したいデータには不向き
  • 2（/home/taro/data）：Node-RED を動かしているユーザーの所有物なので権限の問題が起きず、バックアップもしやすい。mkdir -p ~/data で事前にフォルダを作っておくこと
  • 3（/etc）：システム設定用の場所であり、用途が違う。書き込みには sudo が必要で、一般ユーザーで動く Node-RED からは書き込めない

長期運用で書き込み量が多くなる場合は、USB メモリや SSD を /media にマウントして、そちらへ書くことも検討してください。

12. まとめ

このガイドの要点

  • Linux はドライブレターを持たず、すべてが / から始まる1本のツリーに収まる
  • 大文字と小文字は別物。パスの打ち間違いはここが多い
  • ~ は自分のホーム、. で始まる名前は隠しファイル
  • 覚えるのは3つ：設定は /etc、ログは /var、自分のものは /home
  • ラズパイ固有は /boot/firmware（ハード設定）と /dev（装置）
  • Node-RED の本拠地は ~/.node-red。バックアップは flows.json・flows_cred.json・settings.js・package.json の4点
