1. バージョン管理とは

ファイルの変更を続けていると、「前の状態に戻したい」「いつ、何を変えたのか知りたい」という場面が必ず出てきます。よくある自衛策は、企画書_最終版.docx、企画書_最終版2.docx、企画書_最終版2_修正.docx のようにコピーを取っておくことですが、どれが本当に最新なのか分からなくなり、何をどう変えたのかはファイル名からは読み取れません。

バージョン管理は、この「履歴を取っておいて、いつでも戻れるようにする」作業を、コピーの手作業ではなく仕組みとして行う方法です。Gitはその代表的なツールで、次の3つができます。

  • ファイル一式の状態を、メッセージ付きの記録ポイントとして残す
  • 記録の一覧と、各記録で何を変えたかをあとから確認する
  • 任意の記録ポイントの状態を取り出して戻す

2. 仕組み：リポジトリとコミット

Gitの仕組みは、2つの言葉で説明できます。

リポジトリは、履歴の保管庫です。管理したいフォルダの中に .git という隠しフォルダとして作られ、履歴はすべてこの中に保存されます。保管庫は自分のPCの中で完結していて、インターネット接続や外部のサーバーは必要ありません。

コミットは、記録ポイント1つのことです。「その時点のファイル一式の状態」に、変更内容を説明するメッセージ、日時、記録した人の名前を添えて保存されます。コミットを重ねると、履歴は次の図のように時系列の鎖になります。

初版を作成──→グラフ画面を追加──→しきい値の誤りを修正──→（今ここ）

この鎖には大事な性質があります。コミットは末尾に追加されていくだけで、過去のコミットが消えたり書き換わったりすることはありません。昨日の状態も1か月前の状態も保管庫に残り続けているので、「戻したい」と思ったときに、いつでもその時点を取り出せます。コピーファイルを何個も作る必要がなくなるのは、この性質のおかげです。

差分ではなく「その時点の全体」を記録している

コミットは「前回からの変更メモ」ではなく、その時点のファイル一式の状態そのものを指しています。だから、途中のコミットを順にたどり直さなくても、任意の時点へ一足飛びに戻れます（保存領域は中身の重複をGitがうまく共有するため、コピーを重ねるほどには増えません）。

3. 基本機能は5つ

Gitには多くのコマンドがありますが、機能としては次の5つに整理できます。上の3つが日常の中心で、下の2つは必要になったときに使う機能です。

機能 内容 代表的なコマンド
記録する 変更したファイルのうち記録したいものを選び（ステージング）、メッセージを付けてコミットを作る git add → git commit
見る コミットの一覧（いつ、誰が、何のために）や、変更したファイルの中身の差分を確認する git log、git diff
戻す ファイルを過去のコミットの状態に戻す。コミット前の編集を取り消すこともできる git restore、git checkout
分ける 履歴を枝分かれ（ブランチ）させ、本流に影響を与えずに試作を進める。うまくいったら本流に合流（マージ）する git branch、git merge
共有する GitHubなどのサーバー上の保管庫（リモートリポジトリ）と履歴をやり取りし、バックアップや複数人での共有に使う。使わなくてもGitは完結する git push、git pull

「分ける」のイメージは次のとおりです。青い枝（ブランチ）で試作を進めている間も、赤い本流はそのまま残っています。

初版──→機能追加──→合流（マージ）
└─→試作1──→試作2──┘
💻 手を動かして確かめたい場合（5分）

Gitがインストール済みなら（WindowsはGit for Windows インストールガイド参照）、空のフォルダで次を試すと「記録する」「見る」を体感できます。コマンドはコマンドプロンプトでもmacOS/Linuxのターミナルでも同じです。

フォルダを保管庫にします（.git が作られます）：

git init

メモ帳などでファイルを1つ作って保存したら、記録します：

git add . git commit -m "最初の記録"

ファイルを少し編集して、もう一度 git add . と git commit -m "2回目の記録" を実行し、履歴を見てみます：

git log --oneline

コミットが2行表示されれば、ここまでの説明がそのまま画面で確認できたことになります。

初回だけ名前とメールアドレスの登録を求められることがあります

コミットには「記録した人」が入るためです。画面の指示に従い、git config --global user.name "自分の名前" と git config --global user.email "メールアドレス" を一度実行すれば、以降は聞かれません。

4. Node-REDとの関係

Node-REDのプロジェクト機能は、このGitの上に作られています。プロジェクトを作ると、Node-REDがフローのフォルダをリポジトリにし、エディタの画面から「記録する（コミット）」「見る（履歴の表示）」「共有する（リモートとの同期）」を操作できるようにしてくれます。

つまり、コマンドを覚えなくてもプロジェクト機能は使えますが、画面に出てくる「コミット」「ブランチ」「リモート」という言葉の意味は、ここで説明したものと同じです。裏で何が起きているかが分かっていると、操作に迷ったときや元に戻したいときに、状況を落ち着いて判断できます。

5. 用語ミニ辞典

用語 意味
リポジトリ 履歴の保管庫。フォルダ内の .git に実体がある
コミット 記録ポイント。ある時点のファイル一式＋メッセージ＋日時＋作者
ステージング 次のコミットに含める変更を選ぶこと（git add）
ブランチ 履歴の枝分かれ。本流と並行して別の変更を進められる
マージ 枝分かれした履歴を合流させること
リモートリポジトリ サーバー上（GitHub等）の保管庫。push で送り、pull で受け取る。利用は任意

まとめ

Gitは「コミットという記録ポイントをリポジトリに積み重ね、いつでも見返せる・戻せるようにする道具」です。この一文が腑に落ちていれば、本ガイドの目的は達成です。
